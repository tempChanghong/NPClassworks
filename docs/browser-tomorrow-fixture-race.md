# 明日清单 Browser CI 请求竞争

## 原因与复现

失败用例先通过测试后端加载含有“作业板就绪”的日作业列表，再安装日列表返回空数组的浏览器拦截。核对清单和主作业板使用同一个日列表接口：连接后的刷新或页面恢复刷新若在清单打开期间到达，就会把主作业板由一条作业改为空列表。

清单的作业变化保护因此正常清空结果，`.tomorrow-due` 随之消失。这个时序与 CI 日志中“找不到元素”一致；本机使用旧测试数据、主动触发窗口可见性恢复事件，也确认清单显示“作业已变化”并移除条目。

这次问题与 `baseline-browser-mapping` 的数据过期警告无关。

## 修改

- 页面打开前安装拦截，日列表始终返回同一条测试作业，覆盖启动、清单加载及后台刷新。
- 跨查询版本冲突仅改变周查询返回的同 ID 修订号，不再同时篡改日作业板。
- 测试作业发布时间固定在所用日期的零点，避免浏览器固定为中午时出现时间矛盾。
- 等待班级实时订阅建立后操作清单；主动触发后台刷新，验证内容不变时清单保持可见。
- 保留发布时间跨越、503、版本冲突、晚到响应、跨午夜及无效结果不能导出的断言。

产品代码、测试超时与重试配置未修改。临时复现文件已移除。

- 随后单独运行完整 Browser 套件，131 项全部通过（5.9 分钟）。
- Lint 和差异检查通过。测试修改尚未提交或推送，需推送后由 GitHub Actions 再验证。
