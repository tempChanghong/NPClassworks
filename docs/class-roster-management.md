# 班级学生名单管理

学校管理 → 学生名单，选择学校、学期、年级和行政班。仅 OWNER/ADMIN 可用，服务端再次核验本校权限。

## 操作

- 表格逐项修改学号、姓名、排序；改名和修改学号保留学生内部 ID。
- 从 Excel 复制“学号、姓名”两列，或每行输入一个姓名。默认追加/更新，保留其他学生；也可明确选择整班替换。
- 批量粘贴按学号匹配已有学生；没有学号时只匹配唯一的同名无学号学生。更改学号、无学号学生改名，使用表格编辑，避免将其当成新增学生。
- Excel 两列中的空学号会被保留，姓名内部的空格也会保留；空姓名或多余列会提示错误行，不改动当前名单和粘贴内容。两种导入模式都拒绝同一批中的同名无学号学生，请补充不同学号，或在表格中逐项添加，避免误合并。
- 保存前预览新增、修改、排序、移出。重复学号、空姓名和超过 120 人会被拒绝。
- 移出采用停用，保留学生记录和已保存的考勤。此功能不提供管理员修改每日考勤。
- 保存失败或版本冲突保留输入。重新载入、切换班级或离开管理页时提醒处理未保存内容。

## 同步与一致性

名单仍属于行政班，所有绑定该班的大屏读取同一份名单。名单保存事务锁定班级行，比较读取时的名单版本后写入；管理员和大屏共用这一实现。学生新增、修改、停用及完整前后名单审计在同一事务提交。

提交后发送 `classroom.roster.updated`，事件只包含班级 ID，不广播学生姓名。大屏打开课堂工具时加载最新名单；工具已打开时收到事件、恢复联网或前台会检查更新，并有 60 秒检查兜底。没有未保存修改时刷新；正在编辑名单或考勤则提示重新核对，保留当前输入。关闭页面后释放事件和计时器。

## 接口与部署兼容

- 管理员：`GET/PUT /api/v2/admin/schools/:schoolId/administrative-classes/:classId/students`。响应 `data` 为 `{students, revision}`，保存请求为 `{students, expectedRevision}`。
- 大屏：原 `GET/PUT /api/v2/classroom-screens/students` 保留 `data` 数组结构，在响应顶层增加 `rosterRevision`；保存请求增加 `expectedRevision`。
- 版本由当前名单及更新时间生成，不新增数据库字段，不需要新增数据库迁移。
- 缺少版本的旧版客户端仍可读取名单，保存时返回 428 并提示更新应用、重新载入名单。这是防止旧版大屏覆盖管理员更改的必要保护。版本不一致返回 409，不执行任何名单写入。
- 本功能涉及前后端配套更新。无需修改部署代理或服务器配置；大屏更新前端后再使用名单编辑。
