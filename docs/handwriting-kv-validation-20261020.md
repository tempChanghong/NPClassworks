响应丢失用例先将真实请求交给 KV 并确认事务已完成，再在浏览器端丢弃响应。随后等待现有的首次约 15–30 秒退避，确认自动重试清空队列；再次发送相同 `clientRequestId` 也返回同一作业，没有重复行或修订。未放宽或绕过业务重试规则。

教师端沿用现有离线行为，没有新增离线发布队列；保留当前表单不等于刷新后恢复未保存的教师输入。

本轮补齐的验证设施：

- 测试服务器补齐 JavaScript 模块与 WASM 的 MIME，避免 WASM 流式加载降级；正式部署配置未改动。
- 独立原生数据库入口自动记录提交、工作树指纹、数据库身份和测试结果，不改变常规 fullstack 用例集合。
- Prisma 生成前备份、结束后恢复，检测到并发修改则保留备份并拒绝覆盖；失败也先关闭自有数据库。

早期失败来自测试生成笔迹范围、按钮选择、Service Worker 绕过网络拦截，以及对重试计数和等待时间的错误假设，均修正测试后复跑；未将它们作为业务缺陷计数。
