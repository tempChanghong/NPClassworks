# 大屏列表、背景下载与噪声历史的失败恢复

日期：2026-09-12。

## 大屏管理列表

- 同一学校的手动刷新、自动轮询共用一个正在执行的请求。列表刷新与账号写入分别维护忙碌状态，避免刷新结束误解除写入状态。
- 刷新失败保留上次成功结果和时间，并明确提示设备状态可能已变化。无成功结果时显示错误，不显示“还没有大屏账号”。401/403 则清空旧列表。
- 账号修改等写入成功时，如果旧刷新仍在执行，会追加一次刷新；忽略写入前请求的过时结果。调用方等待追加刷新结束。
- 补测并修复了结果已应用、Promise 清理尚未执行的时序窗口：此时新增的写入后刷新会排在旧请求清理之后执行，不会遗漏。
- 切换学校和组件卸载会取消正在执行的列表请求，并拒绝其迟到结果。

## 背景下载

- 预设选择增加“取消下载”。取消、切换到图片网址、离开设置或关闭背景设置区都会终止该次请求，保留已保存的背景选择。
- 应用显示层切换背景或关闭背景时也取消过时请求。主动取消不会触发旧缓存兜底或联网重试。
- 保留网络请求至完整响应体接收结束的 20 秒超时，新增图片解码 5 秒超时。取消或解码失败会释放临时图片 URL；迟到结果不能重新应用背景。
- 已完成的缓存写入不支持回滚；取消不会清空其他背景缓存或尚未上传的作业。

## 噪声历史

- 可控场景中已复现：IndexedDB 打开请求一直不派发完成/错误事件时，原读取 Promise 一直等待。
- 打开数据库和单次事务分别设置 10 秒超时。发生 `blocked` 时给出被其他页面占用的提示；失败后允许下一次操作重新打开。
- 超时会实际调用事务 `abort()`，并丢弃该连接。没有使用仅结束外层 Promise、让写入继续运行的处理方式。
- 打开请求本身不能直接取消，因此过时请求进入升级时中止其升级事务，迟到打开成功时关闭旧连接，且不会清除新连接的状态。
- 保存超时会显示具体原因；现有串行保存队列可继续处理后续任务。失败的数据不会被宣称为保存成功。本批不增加历史记录自动重试队列。

## 验证依据

- `tests/screenAccountManagerFlows.test.js`：失败保留、权限拒绝、请求合并、写入后追加刷新、切校和卸载保护，以及已有创建/编辑/撤销行为。
- `tests/noiseHistoryTimeout.test.js`：无回调超时、blocked、主动关闭、迟到成功/错误/升级不能影响下一次打开。
- `tests/e2e/admin-screens.spec.js`：真实大屏列表刷新按钮，失败保留并提示、成功重试恢复。
- `tests/e2e/background-presets.spec.js`：真实 HTTP 响应体挂起后取消或离开设置，服务端观察连接关闭；解码超时释放 URL 后重选；原有离线、升级、缓存容量场景。
- `tests/e2e/noise-history.spec.js`：用真实 IndexedDB 的被阻塞删除操作挂住打开请求、用活跃事务阻塞后续写入，验证超时后恢复、旧写入不提交、清空后仅保留新数据。测试使用独立浏览器环境及测试数据库名。

仅修改前端及测试，不修改后端、数据库结构或部署代理。
