# 通知回执、麦克风生命周期和噪声历史优化

日期：2026-09-06。仅本地代码和隔离测试；没有推送或部署，没有修改 `deploy/agent/server.js`。

## 通知回执

后端原实现先读取发布版本和已有回执，再进入写事务。真实 PostgreSQL 测试复现了：

- 迟到的旧版本回执覆盖新版已确认回执。
- 同版并发回执、同批重复条目清空已确认状态。
- 通知撤回后，已在等待的请求仍新建回执。
- 同时创建回执时出现唯一约束冲突。

现在同一大屏的回执批次在事务中串行写入。事务内再次核验绑定状态和凭据，并锁定通知后重新读取版本、状态及回执；同版回执只推进状态，新版才重置显示和确认时间。批次按通知 ID 排序获取锁，减少多通知批次的锁顺序冲突。

接口请求和响应结构保持不变，无数据库结构迁移。旧前端可继续调用。

后端回归位于 `tests/notificationDeliveryDatabase.integration.test.js`，已加入 `scripts/run-database-tests.js`，随现有数据库测试部署门槛执行。测试使用本机临时 PostgreSQL，延迟真实事务的入口以控制时序，所有业务读写均访问实际数据库。

## 麦克风

启动、Worklet 加载、AudioContext 恢复和设备测试使用操作代次；停止使旧操作失效。迟到的流立即停止其轨道，旧失败和旧轨道结束事件不会改变新会话。释放资源时先同步摘除旧引用，再异步关闭 AudioContext，防止慢关闭清空新资源。

定时监测不再等待授权请求完成才处理取消。关闭计划、关闭工具、解绑、切换绑定和卸载均覆盖测试。设备输入测试也支持取消，并且取消后不会自动恢复监测。

生命周期测试使用可控音频 API 夹具和实际服务代码，调度及历史界面测试挂载实际 Vue 组件逻辑。它们不等同于实物麦克风或所有浏览器驱动测试；系统授权对话框本身不能由这些代次检查关闭。

## 噪声历史

使用独立 IndexedDB 数据库 `classworks-noise-history`，每次仅写入一个统计片段。仍保留最近 14 天、最多 5,000 条噪声统计；过期和超量条目在同一事务内清理。作业缓存和待上传队列不属于该数据库，不参与清理。

第一次使用时自动将 `noise-slices-v2` 的有效历史迁入。只有事务提交成功才删除旧副本；迁入失败保留源数据并可重试。迁入标记防止清空历史后再次导入残留副本。浏览器不支持 IndexedDB 时保留旧存储方式；运行中的 IndexedDB 错误会显示保存/读取失败，不会静默切换到另一份历史。

读取与清空改为异步；迟到的读取不能覆盖已清空的界面。保存失败会显示提示，后续保存仍可继续。清空与进行中的保存按顺序执行。

这是浏览器本地历史的一次自动迁入，不需要修改服务器。若回退到旧前端，旧版不会读取 IndexedDB 中的新历史；升级回来后数据仍可读取。迁入完成前仍在运行的旧页面，应刷新至新版后继续记录。

## 性能实测

复现命令：`node scripts/benchmark-noise-history.js`。隔离 Chromium、合成 5,000 条统计，旧 JSON 为 1,778,891 字符。每种方式先预热 5 次，再采样 40 次。

| 指标 | 旧同步重写 | IndexedDB 增量写入完成时间 |
| --- | ---: | ---: |
| 中位耗时 | 7.8 ms | 0.4 ms |
| P95 | 8.8 ms | 0.6 ms |
| 最大值 | 9.3 ms | 0.7 ms |

首次自动迁入约 127.7 ms，包含读取、导入和返回历史，仅发生一次。IndexedDB 数字包含等待异步事务提交的时间，不是主线程 CPU 占用或画面帧率。这些结果来自开发机，尚未在课堂低配设备实测。
