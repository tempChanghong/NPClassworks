# 手写作业正文

大屏“录入作业”和教师“新建发布／编辑／复用作业”的必做、选做正文均提供“手写输入”。标题、科目、班级、日期仍由原表单填写。

## 使用与保存

1. 先选好科目、班级，在正文中放好插入光标或选中要替换的文字。
2. 点击手写输入，每行写一段，点击“识别文字”。首次识别按需准备约 23 MiB 的本机资源。
3. 识别结果可以修改。点击“插入正文”后才填回原表单；仍需原来的保存、保存草稿或发布操作。

手工校对或选定候选后，笔迹未变时再次点击识别会保留当前文字；新增笔迹后重新识别，会先确认是否替换校对内容。插入完成后恢复正文焦点和光标，可以直接继续键盘录入。

只保存确认后的 `content` 和 `contentJson.optionalContent` 文字。笔迹、图片、候选、特征和模型输入均不提交服务器，也不进入作业草稿或大屏离线队列。本次没有接入个人手写记忆或自动学习。手写区未确认内容只在当前页面内存中，关闭会询问是否放弃；刷新或浏览器回收不能恢复这些笔迹。

切换班级、科目、日期、绑定凭证、账号、作业版本或编辑正文后，旧任务不能插入，即使随后切回原值也不能恢复旧任务的权限。撤销插入也不能覆盖更晚的编辑。

## 性能和离线

- 入口不启动模型。编辑器在点击后加载，识别资源和 Worker 在明确识别后才启动。资源不进入普通 PWA 预缓存。
- 沿用独立验证的 r19：单线程 FP32 推理、一个推理 Worker、最多三块输入缓冲（总容量约 2.53 MiB）。资源准备 Worker 在推理前退出；关闭、切到后台或原有 15 秒空闲规则释放推理会话。不强制 GC，不缩短空闲时间来隐藏识别期间内存。
- 完整资源经过 SHA 校验并存入本机后，受 Service Worker 控制的网页/PWA 可离线识别。浏览器清理或回收缓存后，需要重新联网准备。首次离线不承诺识别，保留笔迹和原正文并提示重试。
- 确认的文字走原保存流程。大屏离线时进入原待提交队列，联网后补传；教师端沿用既有保存失败与保留输入行为，不宣称新增教师离线发布。
- 部署需要浏览器支持安全上下文、WebAssembly SIMD、Worker 和 Cache Storage。资源 URL 从构建模块位置解析，与当前 SPA 页面路径无关。此模块不需要开启跨源隔离或多线程。

23 MiB 是资源体积，不能当作识别内存占用。测试分别记录完整浏览器进程组的 PrivateBytes、页面 JS 堆与模型耗时，不能用页面堆代替总内存。

## 固定资源与许可

`public/handwriting/r19` 的 19 个文件从独立验证 r19 原字节复制，`src/features/handwriting/pinned-resources.json` 固定大小和 SHA。构建在缺失、损坏时失败，Git 禁止对这些载荷转换换行。模型权重、字典、输入尺寸和中文数字／0/O／1/l／范围语境规则未重新训练或降精度。

模型为 RapidOCR 发布的 PP-OCRv6 small，经独立实验转换为 ORT FP32、TopK(5) 输出；运行库来自 ONNX Runtime 1.30.0 的既有精简 SIMD 构建。r19 包含实验中验证的 SGEMM 改动及模型缓冲所有权适配。完整来源、上游 SHA 和转换说明随 `assets/manifest.json` 分发；ONNX Runtime MIT、PaddleOCR/RapidOCR Apache-2.0 许可证随 `public/handwriting/licenses` 分发。不要只替换某一个运行库文件。

## 隔离复验

```powershell
pnpm test
pnpm run lint:check
$env:E2E_WEB_PORT = '4206'
$env:E2E_API_PORT = '4207'
pnpm exec playwright test --config playwright.handwriting.config.js
```

浏览器测试构建真实生产页面、Service Worker 和模型，只连接回环内存 HTTP 夹具，不连接学校或数据库。独立配置默认使用开发电脑的 Edge；常规 CI 使用已安装的 Chromium 运行同一用例。生成字体只验证集成前后的输出一致性，CDP 触控和 DPR2 只验证对应模拟层。实体一体机真人新笔迹、真实触控/Windows 200% 缩放、已安装 PWA 和实际 KV 保存仍需现场验收。
