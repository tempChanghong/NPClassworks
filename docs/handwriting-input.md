# 手写作业正文

大屏“录入作业”和教师“新建发布／编辑／复用作业”的必做、选做正文均提供“手写输入”。标题、科目、班级、日期仍由原表单填写。

## 使用与保存

1. 先选好科目、班级，在正文中放好插入光标或选中要替换的文字。
2. 点击手写输入，每行写一段，点击“识别文字”。首次识别按需准备约 23 MiB 的本机资源。
3. 识别结果可以修改。点击“插入正文”后才填回原表单；仍需原来的保存、保存草稿或发布操作。

识别期间，固定右上角的“返回录入”切换为“取消识别”，无需向下滚动寻找。取消只停止本次任务，保留笔迹和已校对文字，可以直接再次识别，不必清空。浏览器识别锁和每次 Worker 请求均有 90 秒等待上限；异常超时同样保留内容，迟到的旧回调不能结束新任务。

首次下载编辑器期间若改点另一个正文的手写入口，只打开最后选择的入口，不叠加多个手写区；取消或关闭后不会再弹出先前的入口。原正文始终保留。

手工校对或选定候选后，笔迹未变时再次点击识别会保留当前文字；新增笔迹后重新识别，会先确认是否替换校对内容。插入完成后恢复正文焦点和光标，可以直接继续键盘录入。撤销本次插入后也会恢复原选区；后续输入或编辑范围已变化时，不撤销或移动光标。

只保存确认后的 `content` 和 `contentJson.optionalContent` 文字。笔迹、图片、候选、特征和模型输入均不提交服务器，也不进入作业草稿或大屏离线队列。本次没有接入个人手写记忆或自动学习。手写区未确认内容只在当前页面内存中，关闭会询问是否放弃；刷新或浏览器回收不能恢复这些笔迹。

切换班级、科目、日期、绑定凭证、账号、作业版本或编辑正文后，旧任务不能插入，即使随后切回原值也不能恢复旧任务的权限。撤销插入也不能覆盖更晚的编辑。

教师在另一窗口重新登录或清除登录时，旧手写选区同样失效；普通访问令牌续期保留当前登录，不会因此取消手写。该判断只在页面内存中使用凭证身份，不把凭证加入正文、草稿或识别请求。

## 性能和离线

- 入口不启动模型。编辑器在点击后加载，识别资源和 Worker 在明确识别后才启动。资源不进入普通 PWA 预缓存。
- 首次打开面板期间可点“取消打开”，正文保留；切到另一正文或编辑范围变化也会结束原入口的等待。组件下载共用最多 90 秒的等待，超时后可通过独立构建入口重试，有限重试全部失败时提示先保存正文再刷新。取消只结束当前字段的打开意图，仍在进行的共享下载完成后不会自行弹出旧面板。识别中可随时用固定页头的“取消识别”保留笔迹与校对文字，不必清空笔迹。
- 沿用独立验证的 r19：单线程 FP32 推理、一个推理 Worker、最多三块输入缓冲（总容量约 2.53 MiB）。资源准备 Worker 在推理前退出；关闭、切到后台或原有 15 秒空闲规则释放推理会话。不强制 GC，不缩短空闲时间来隐藏识别期间内存。
- 完整资源经过 SHA 校验并存入本机后，受当前应用 Service Worker 控制的网页/PWA 可离线识别。“识别资源已缓存”只说明资源已存储；当前页面没有 Service Worker 控制时另行提示保持联网，因为缓存本身不能让 Worker 在断网后加载运行库。浏览器清理或回收缓存后，需要重新联网准备。首次离线不承诺识别，保留笔迹和原正文并提示重试。
- 确认的文字走原保存流程。大屏离线时进入原待提交队列，联网后补传；教师端沿用既有保存失败与保留输入行为，不宣称新增教师离线发布。
- 部署需要浏览器支持安全上下文、WebAssembly SIMD、Worker 和 Cache Storage。资源 URL 从构建模块位置解析，与当前 SPA 页面路径无关。此模块不需要开启跨源隔离或多线程。

23 MiB 是资源体积，不能当作识别内存占用。测试分别记录完整浏览器进程组的 PrivateBytes、页面 JS 堆与模型耗时，不能用页面堆代替总内存。

## 固定资源与许可

`public/handwriting/r19` 的 19 个文件从独立验证 r19 原字节复制，`src/features/handwriting/pinned-resources.json` 固定大小和 SHA。构建在缺失、损坏时失败，Git 禁止对这些载荷转换换行。模型权重、字典、输入尺寸和中文数字／0/O／1/l／范围语境规则未重新训练或降精度。

模型为 RapidOCR 发布的 PP-OCRv6 small，经独立实验转换为 ORT FP32、TopK(5) 输出；运行库来自 ONNX Runtime 1.30.0 的既有精简 SIMD 构建。r19 包含实验中验证的 SGEMM 改动及模型缓冲所有权适配。完整来源、上游 SHA 和转换说明随 `assets/manifest.json` 分发；ONNX Runtime MIT、PaddleOCR/RapidOCR Apache-2.0 许可证随 `public/handwriting/licenses` 分发。不要只替换某一个运行库文件。

## 隔离复验

```powershell
pnpm test
pnpm run lint:check
$env:E2E_WEB_PORT = '4206'
$env:E2E_API_PORT = '4207'
pnpm exec playwright test --config playwright.handwriting.config.js
```

以上浏览器测试构建真实生产页面、Service Worker 和模型，只连接回环内存 HTTP 夹具，不连接学校或数据库。独立配置默认使用开发电脑的 Edge；常规 CI 使用已安装的 Chromium 运行同一用例。生成字体只验证集成前后的输出一致性，CDP 触控和 DPR2 只验证对应模拟层。

### 真实 KV 与临时 PostgreSQL

本机需要已安装的原生 PostgreSQL 工具和 Edge，以及相邻 `NPClassworksKV` 的依赖。运行：

```powershell
# 非默认工具目录可先设置：
# $env:NPEP_TEST_PG_BIN = 'C:\Program Files\PostgreSQL\17\bin'
pnpm run test:handwriting:kv
```

入口自动分配三个回环端口，新建带随机口令的自有 PostgreSQL 集群和空测试库，只向该库执行现有迁移；不读取现有数据库连接、不使用 Docker、不连接学校服务。浏览器运行正式构建、Service Worker 和实际模型，HTTP 保存由真实 Express/Prisma/PostgreSQL 处理。测试放在独立目录，不加入常规 fullstack 用例集合。

覆盖大屏与教师的必做/选做保存、草稿、历史复用、切班、真实 409 冲突、大屏断网刷新补传、提交已成功但响应丢失后的去重，以及教师离线保存失败后手动重试。请求、数据库正文、修订历史、审计和本地草稿/补传队列均检查仅含确认后的文字。大屏瞬时网络失败使用原有约 15–30 秒首次退避，不把瞬间仍在队列中判为补传失败。

结果与日志写入忽略目录 `.artifacts/handwriting-kv/<本次编号>/`，以该次 `result.json` 为准。记录源码提交及工作树指纹；测试期间不要编辑相关源码。Prisma 客户端生成前备份原字节，结束后恢复；若检测到并发修改则停止覆盖并保留备份。成功时关闭并删除自有临时集群；失败时保留已停止的集群供诊断。

真实 KV 隔离联调已经覆盖本地数据库保存，详见 [2026-10-20 验证记录](handwriting-kv-validation-20261020.md)。实体一体机真人新笔迹、真实触控/Windows 200% 缩放、已安装 PWA 和生产服务仍需现场验收；本地数据库通过不代表现场通过。

### 自托管静态文件

识别运行库的 `.mjs` 必须以 `application/javascript` 返回，不能是 `application/octet-stream`，否则浏览器的模块导入会因严格 MIME 检查失败。`deploy/nginx.conf` 显式提供该映射，并让缺失模块返回 404，避免被 SPA 文档替代。自建反向代理也应保留模块和 WASM 的正确类型。

Store 构建与生产部署检查会在 Linux CI 用原生 Nginx、候选 `dist` 和实际生产 server 配置执行 `bash scripts/check-nginx-static.sh dist`。测试仅监听回环地址，覆盖模块、WASM、普通脚本、JSON、HTML 和缺失模块；上层 MIME 表有意不预设 `.mjs`，确保不会因 CI 系统默认值较新而掩盖旧运行镜像的问题。Windows 本地不将 shell 语法检查当作这项 Nginx 运行验收。
