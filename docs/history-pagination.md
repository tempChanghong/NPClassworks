# 历史分页（2026-09-06）

版本历史弹窗首次请求 20 条，点击“加载更早版本”再追加 20 条。后端按版本号游标返回，不用偏移分页；期间新增版本不会改变已加载旧页的位置。已加载页面继续保留在界面内，因此连续手动加载全部历史后仍会占用相应内存。

追加页失败时保留已有内容和游标，按钮可重试。首屏失败可点击“重新加载”。关闭、切换作业或切换教师/大屏模式会使旧请求失效；同一作业对象更新不会重复触发首页请求。恢复、确认当前版本或发生版本冲突后重新加载最新首页，原有恢复权限和冲突处理保持不变。

新后端返回 `{items, nextBeforeRevision}`。为兼容分离部署的过渡期，遇到旧后端的完整数组时先在客户端分页显示；此时只减少首次渲染量，传输量仍要等后端更新才会减少。旧前端不带分页参数的请求仍由新后端按原格式响应。

验证：前端 208 项测试、8 项 Chromium E2E、ESLint、生产构建和 PWA 校验通过。新增交互测试覆盖教师/大屏、新旧接口、追加失败重试、防止重复点击、切换作业后旧响应丢弃。浏览器实际验证 45 条历史按 20/20/5 显示，从最后一页恢复版本 1 后出现版本 46，首页仅重新请求一次。

后端真实数据库同时验证分页、恢复和备份恢复，详见后端 `docs/backup-restore-and-history-pagination.md`。本次没有新增数据库迁移，也没有改动部署代理或执行推送部署。
