# 发布前预览、提交说明与更正原因

## 发布前大屏预览

教师作业编辑器底部选择“预览大屏效果”。填写科目、目标班级、正文或标题及有效日期后，可按所选班级逐个预览。本次输入中的正文、无作业标记、需带物品、携带日期、提交说明和截止时间均参与预览。

预览复用实际大屏作业卡片，明确显示“尚未发布”。它只检查和展示本次输入，不保存草稿、不发送发布请求，也不改变大屏内容。返回编辑后原输入保留。账户、会话或编辑对象改变时关闭旧预览。

实际设备的字号、列数和主题可能不同；预览采用单列排版。教师确认状态和发布权限仍以服务器保存结果为准。多班切换只显示所选目标的名称，不把本次作业误当成该班当前完整作业板。

## 作业提交说明

普通作业可选填最多500字的提交说明，例如“早读前交给数学课代表，订正在原卷上”。没有填写时不占展示空间。切换为“今日无作业”时不提交这项说明，避免出现无作业却需要上交的矛盾信息。

说明出现在大屏、学生作业板、临时放大、抄写模式、打印、图片和版本历史中。修改说明会参与大屏更正提示和冲突比较，沿用原作业的权限、实时同步及离线缓存流程。

个人模板可保存提交说明，支持“交给〔课代表〕”等填空项。模板没有提交说明时保留编辑器已有说明；旧客户端编辑模板而未发送该字段时，后端保留已有值，明确发送空字符串才清除。

## 本次更正原因

教师编辑已发布作业时可选填最多300字的原因，例如“课堂进度调整，只完成前三题”。大屏发生内容更正时同时展示原因，版本历史保留本次说明。

原因属于一次编辑，不是作业模板内容。重新进入编辑器时原因留空；下一次编辑未填写原因时，当前版本不沿用旧原因。复制、历史恢复、大屏编辑也不沿用来源原因，原历史版本中的说明继续保留。仅填写原因而未改变作业内容不会额外触发作业内容变化提示。

## 接口与部署

- 提交说明保存在已有 `Publication.contentJson.submission` 字符串中。
- 修改已发布作业的 PATCH 请求可带顶层 `correctionReason`；服务器验证后写入本次 `contentJson.correctionReason` 及修订快照。客户端直接在元数据中携带的旧原因会被清除。
- 模板新增可选 `submission` 字段，仍按教师账号隔离，采用原有版本冲突保护。
- 预览与实际提交使用同一个表单序列化函数；预览不调用发布接口。

无需数据库迁移或修改部署代理。建议先更新后端，再更新前端；旧前端不会展示新增信息。
