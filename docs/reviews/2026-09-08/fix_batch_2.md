## F2：停用走班不再阻断正常班级作业

- 后端课程目录同时排除停用和不可供学生选择的走班；领域层也过滤这些状态，选择校验不会接收已停用走班。
- 学生刷新页面时，沿用已有启动校验移除失效走班并提示重新确认；保留行政班和其他有效走班。
- 已打开的作业板遇到 `WORKSPACE_NOT_FOUND` 时，重新读取当前行政班目录；只有确认走班选择发生变化，才保存修正后的选择并重试一次。其他有效班级的作业继续显示，用户可重新选班。
- 普通网络错误不触发选班清理。目录不可用、目录未变化或再次请求仍失败时，不无限重试。迟到的目录结果不能覆盖新选班，作业结果也检查选班与日期是否仍匹配。
- 选班弹窗提交被服务端拒绝后刷新目录，清除已失效的临时选项；必须选择实际可用的教学班（或允许的不修读选项）才能保存。

后端真实数据库测试验证停用前可见、停用后目录排除及校验拒绝、重新启用后恢复可选。前端 Store 测试覆盖保留有效选择、持久化、有限重试、网络故障及迟到结果隔离。真实 Chromium 验证旧选择跨刷新恢复、重新选班保存、已打开弹窗被拒绝后的更新，以及运行中停用后的作业板恢复。

## F3：导入遵守已有教学空间的身份约束

组织预检新增数据库核验，正式导入在事务开始写入前重复核验。校验失败沿用 422 结果，提供文档路径、教学空间 ID、错误码和原因，整批拒绝写入。

| 变更 | 规则 |
| --- | --- |
| 同学期同代码的类型变更 | 拒绝，返回 `WORKSPACE_TYPE_LOCKED` |
| 同学期同代码转移年级 | 拒绝，返回 `WORKSPACE_GRADE_LOCKED` |
| 有作业目标引用或任课关系的走班更换科目 | 拒绝，返回 `COURSE_GROUP_SUBJECT_LOCKED`；停用的任课关系也计入 |
| 普通重命名 | 允许 |
| 无作业目标引用且无任课关系的空教学班更换科目 | 允许 |

单独编辑走班与组织导入共用科目保护规则，单独编辑也在写事务中重新读取引用。数据库测试检查预检和直接导入的拒绝结果、失败后学校名称和科目没有部分更新、预检后新增历史，以及服务内初步检查与事务开始之间新增历史的情况；正常重命名和空教学班换科目作为正向对照。

这里验证的是预检与写入入口的一致性，以及事务写入前的重新检查；没有将其描述为所有组织写入与发布写入之间的全面并发串行化。历史保护沿用作业目标引用，并增加任课引用检查，没有新增扫描历史快照表的流程。
