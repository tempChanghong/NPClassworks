# 第四批修复：跨标签草稿、离线队列与刷新保护

日期：2026-09-08。范围：工程报告 F5、F7。仅修改前端，沿用第三批的临时退出期限和会话清理规则。

结果：本批范围内修复完成，最终回归通过。兼容和资源生命周期边界见下文。

## F5：避免标签之间覆盖或清除待提交内容

原草稿使用同一绑定、同一作业的公共键，一个标签保存成功即可删除另一标签的草稿；原队列对整个数组读改写，没有跨标签互斥。这些原行为由源码确认，本批没有在旧版浏览器上另跑一轮失败基线，不将回归结果描述为原版实测复现。

- `screenDraftSession.js` 为草稿增加标签身份，并通过文档存续期间持有的 Web Lock 识别复制标签造成的 sessionStorage 副本。正常刷新沿用身份，复制出的新标签使用独立草稿键。
- 原格式草稿按“先复制成功、再删除来源”迁入；重新打开标签可恢复已关闭标签的草稿，但不能接管仍在使用的草稿。获取原标签所有权后重新读取最终内容，避免遗漏原标签关闭前的最后一次保存。
- 草稿仍采用已有七天过期规则；尚未上传的作业队列不按该规则删除。读取、迁移或持久化失败继续保留来源与输入，并提供错误状态。
- `ScreenHomeworkDialog.vue` 异步准备草稿存储期间暂停编辑和提交；关闭窗口、切换绑定或切换作业后的旧读取结果不能覆盖当前表单。成功保存、放弃恢复、冲突覆盖及另存副本只清理本标签的草稿。
- `screenPublicationQueue.js` 提供按绑定队列键加锁的变更入口。Store 的新增、删除、失败状态更新全部在锁内重新读改写；锁不包住网络请求。其他标签通过 storage 事件更新列表并安排补传，服务端原有请求 ID 幂等机制继续负责重复请求。
- 队列动作等待锁后重新核对当前上下文，避免将旧绑定结果写入新绑定的界面状态。

**兼容边界：** 协调依赖浏览器 Web Locks。在不支持的浏览器或非安全上下文中，相关保存明确失败并保留输入，不退化为无跨标签保障的成功提示。历史已加载的旧代码不会自动遵守新锁；部署后应在保存当前输入后更新所有同时运行的旧标签。本批没有声称解决新旧代码混用时的全部队列竞争。

## F7：刷新前检查编辑与保存状态

`appReloadProtection.js` 汇总组件注册的实时检查，供 PWA 更新、设置页刷新、资源恢复刷新及原远程重载保护使用。教师编辑器有未保存变更或请求进行中、大屏录入窗口尚未结束、学校管理页有未保存内容时，会显示阻止刷新原因。组件卸载会释放检查。

浏览器主动刷新、关闭和整页离开接入 beforeunload，由浏览器显示原生确认；站内的刷新按钮不会提供绕过检查的强制刷新选项。浏览器强制终止、崩溃及用户在原生提示中确认离开仍不能由页面代码阻止。本批不声称为所有站内路由新增统一离开保护；管理页继续使用已有路由确认和到期锁定逻辑。

教师正常保存或发布完成、表单重置且无其他阻止条件后，可以刷新。已持久化的后台待上传队列本身不禁止刷新，恢复后仍使用原补传流程。

## CI 选班测试竞争修正

后续 [GitHub Actions 34236959712](https://github.com/tempChanghong/NPClassworks/actions/runs/34236959712) 的 browser 任务为 56 项通过、1 项超时。已下载其 `production-browser-test-results` 原始产物，读取 Linux Chromium trace；该次失败与前述本地并行构建目录干扰不同。

trace 显示第 80 行 `save.click()` 开始后一直等待按钮恢复可用，直到 45 秒测试期限；此前唯一校验 POST 是页面初始化时的成功校验，没有发出测试预期的第二次拒绝请求。夹具在点击前将统一 `stopped` 标记设为真，后台 feed 请求先收到 404，随后目录更新和行政班 feed 恢复为 200。页面正常移除失效选班、禁用保存按钮，破坏了测试即将点击的前置条件。最终 `finally` 手动关闭 context 的错误覆盖了原动作的报错位置。`baseline-browser-mapping` 的数据过期提示不是此次失败原因。

修正仅涉及 `tests/e2e/student-selection.spec.js`：

- 将合并场景拆为两项。提交拒绝场景在校验 POST 到达时模拟停用，并在点击前主动触发后台刷新，验证后台刷新不再抢先改变本场景的前置条件；继续断言真实 422、旧选项消失、新选项出现和保存按钮禁用。
- 独立验证 CI 实际发生的另一种先后顺序：选班窗口打开时停用走班，经真实 Socket 事件刷新后，按钮禁用、未发出额外提交、失效选择持久化清除、行政班作业恢复、手动刷新仍可用。
- 恢复请求检查关注先请求旧走班、再仅请求行政班的顺序及最终状态，允许重连等原因产生的合法额外刷新。
- 使用 Playwright 自带 page/context fixture 管理关闭，保留原失败动作的诊断。没有增加全局超时、启用失败重试或跳过断言。
