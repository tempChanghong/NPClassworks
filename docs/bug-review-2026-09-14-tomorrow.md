# 明日核对清单回归审查（2026-09-14）

本轮在已实现的功能上确认并修复两处问题，均有修复前失败、修复后通过的测试证据。

## 不同查询可能拼接出矛盾版本

清单并行读取日列表和按截止日期查询的列表。老师在读取期间修改作业时，同一作业可能在日列表中仍为“未设截止”，在截止列表中已为“明天要交”；已删除的旧需带物品也可能被保留。

现在对日列表、需带物品及截止查询的原始分页检查同一 ID 的修订号，发现冲突即失败并提示刷新，不提供展示和导出结果。检查发生在周查询按 ID 去重之前，也能发现跨分页出现的不同修订。单元测试覆盖两种返回版本组合及分页冲突；学生与大屏浏览器测试确认冲突后无旧条目或导出入口。

边界：这不是数据库事务快照，无法据此发现从所有响应中完全缺失的记录，也不保证获知未送达的实时事件。

## 无关通知误清空清单和导出图片

实际 Socket 消息将发布类型放在 `content.publicationType`，组件原先读取顶层字段；另外，作业列表失效标识包含通知。两处都会使正常通知更新被当成作业变化，从而清空核对清单并卸载打印窗口，已生成图片随之释放。

现在按实际消息结构识别通知，列表失效标识只包含作业。真实 PostgreSQL + HTTP + Socket.IO + 浏览器测试复现：不弹窗的次要通知到达后，打印窗口原先消失；修复后窗口及图片保留。该流程继续验证作业撤回仍使清单失效。
