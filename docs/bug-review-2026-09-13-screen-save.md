# 大屏保存边界审查与修复（2026-09-13）

本轮在前端 `a274646`、后端 `9e984cb` 基础上检查大屏录入与连续版本冲突。本轮业务改动仅涉及前端 `src/components/v2/ScreenHomeworkDialog.vue`。

## 已修复问题

### 1. 保存期间仍可输入，成功后可能丢失后续修改

新建和修改作业均存在：请求已携带提交时的表单快照，输入框、科目和快捷输入仍可操作。保存成功后会清除草稿并关闭窗口，因此请求发出后接受的新输入不在该请求内，也可能失去草稿。

延迟请求测试确认，旧代码在等待响应时可以继续输入。修复后，保存、冲突提交、另存和载入期间将整个编辑卡片设为不可交互，并标记繁忙状态；各请求入口也检查繁忙状态，避免重叠操作。请求失败后恢复输入，允许修改并重试。原有已提交内容和保存后关闭窗口的交互保留。

### 2. 连续冲突后读取失败，没有正确处理错误和过期对比

先触发版本1与版本2的冲突，再在确认提交前将服务器更新为版本3。第二次提交返回409后，将读取最新版的GET模拟为503：旧代码的嵌套await没有捕获该错误，界面仍显示版本2的对比，而没有清楚说明读取失败。

修复后先丢弃已失效的对比，记录新冲突版本，再尝试读取；读取失败被捕获并显示具体错误及本机输入保留提示。此时不提供基于旧对比的合并按钮，仍可明确选择载入最新版或另存新作业。恢复读取后可继续编辑、保存。

### 3. 保存失败提示被通用HTTP错误覆盖

422响应提供具体业务说明时，保存处理器只读取 `error.message`，遮住状态层已经解析的错误信息，最终显示 `Request failed with status code 422`。

修复后使用现有 `describeApiError`，优先显示验证详情或服务器业务说明。回归验证明确说明可见，原输入保留且可以修改后保存。

## 测试稳定性修正

`tests/screenFeedScopeFlows.test.js` 的起始作业板日期取当天，而后续固定切换到2026-09-13。当天恰好为该日期时，实际没有切换，测试会错误地要求清除当前有效缓存。已明确起始日期为2026-09-12，保留原有不同日期缓存隔离断言。
