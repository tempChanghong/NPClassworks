# Classworks 学生端、教师端与大屏端三模式改造规划

> 实施状态（2026-08-10）：阶段 A、B、C 已完成；阶段 D 已完成共享作业网格拆分、单元测试、数据库集成测试和浏览器回归。教师工作台仍保留在 `ClassworksHome.vue` 中，后续可在不改变行为的前提下继续拆分。

## 1. 目标与结论

Classworks 正式主页应从当前的“学生 / 教师”二态，升级为三个明确的运行模式：

1. **学生端**：学生按自己的行政班和走班组合查看作业，优先适配手机和个人电脑。
2. **教师端**：教师登录后发布、认证、修改和恢复作业，面向个人办公设备。
3. **大屏端**：绑定行政班的一体机自动进入，展示该行政班应当知晓的完整作业，并提供大屏录入、版本恢复和课堂工具。

大屏不能继续被视为“带录入按钮的学生端”。它的身份、作业范围、默认布局和显示设置都与学生个人浏览器不同，应当独立建模。

本次改造不改变已经确定的基本规则：

- 学生仍然自行选择行政班和实际参加的走班。
- 一、二班的小科随行政班时，不要求选择走班；其全科作业由行政班空间承载。
- 三至七班或八班的小科按学校实际配置选择走班，不在前端硬编码具体班级数量和科目组合。
- 大屏录入的每次保存继续产生不可删除的版本；教师发布或认证为“已认证”，非教师修改已认证作业后重新变为“未认证”。
- 课堂工具只对已绑定大屏开放。

## 2. 当前实现与主要问题

当前 `ClassworksHome.vue` 只有 `student` 和 `teacher` 两个模式。浏览器具有有效大屏绑定时，学生模式会额外显示“课堂工具”和“大屏录入”，但没有独立的大屏布局。

当前学生作业流由 `selectedWorkspaceIds` 加载，包含：

- 学生选择的行政班；
- 学生为每个走班科目选择的一个教学班。

这对学生是正确的，但对班级大屏不正确。大屏如果沿用某次个人选班结果，就可能漏掉同一行政班其他学生参加的走班。例如三班学生分别参加物理 A1、A2 时，三班大屏应能展示与三班有关的 A1、A2 作业，而不是只展示浏览器本地恰好选中的一个班。

后端大屏会话目前返回行政班和同年级相应科目的全部走班空间，还需进一步限定为“来源行政班包含当前绑定行政班”的走班空间，避免把与本班无关的教学班加入大屏范围。

此外，大屏目前没有字体缩放、紧凑布局、列数等显示设置，后排可读性无法保证。

## 3. 三种模式的职责边界

| 能力 | 学生端 | 教师端 | 大屏端 |
| --- | --- | --- | --- |
| 身份来源 | 无需登录，本地选班 | 学校代码 + 短账号 + PIN；OAuth 可选 | 管理员一次性绑定后保存大屏令牌 |
| 作业范围 | 本人的行政班 + 本人选择的走班 | 有教学权限的工作区 | 绑定行政班 + 所有与该行政班相关的走班 |
| 默认设备 | 手机、平板、个人电脑 | 教师个人设备 | 教室一体机 |
| 查看作业 | 是 | 是，主要通过管理列表 | 是 |
| 发布与修改 | 否 | 是 | 仅作业，可录入和修改允许范围内的单目标作业 |
| 认证作业 | 否 | 是 | 否 |
| 恢复历史版本 | 否 | 是 | 是，仅限大屏可编辑的作业 |
| 修改选班 | 是 | 不适用 | 否 |
| 课堂工具 | 否 | 默认不提供 | 是 |
| 显示设置 | 跟随响应式布局 | 跟随响应式布局 | 字体、密度、列数、时间卡片等专用设置 |

三种模式是同一应用内的三种界面，不是三套独立项目。它们共享发布数据、认证状态、历史版本和实时同步协议。

## 4. 进入模式与切换规则

### 4.1 默认进入规则

- 浏览器存在有效大屏绑定：初始化完成后默认进入 `screen`。
- 浏览器没有大屏绑定：默认进入 `student`。
- 教师登录不会强制跳转；登录成功后进入或保留 `teacher`。
- 大屏令牌失效时，显示明确的“绑定已失效”提示并退回 `student`，不得继续显示大屏写入能力。

### 4.2 顶部模式切换

- 普通浏览器显示“看作业 / 教师”。
- 已绑定大屏只显示大屏界面，不提供“看作业 / 教师”切换入口，避免教室一体机进入个人选班或教师工作台。
- 大屏会话认证成功后直接进入 `screen`，不再显示模式切换控件。
- 大屏令牌失效后才恢复普通浏览器的“看作业 / 教师”入口。

### 4.3 初始化顺序

主页初始化调整为：

1. 并行加载学校公共信息、教师会话和大屏会话；
2. 根据有效大屏会话决定默认模式；
3. 只加载当前模式需要的作业流；
4. 建立当前作业范围的实时订阅；
5. 模式改变时原子地切换作业流和 Socket.IO 房间。

## 5. 工作区范围规则

### 5.1 学生端

学生作业范围保持为：

```text
学生作业范围 = 行政班工作区 + 每个需要走班的科目所选教学班
```

行政班的科目规则是学校配置的唯一依据：

- `ADMIN_CLASS`：该科目随行政班，不出现走班选择。
- `COURSE_GROUP`：该科目必须或允许选择一个实际教学班。

因此，一、二班是否全科随行政班由后台科目规则决定，不在代码中写死“一班、二班”。未来学校调整分班方案时只需修改组织配置。

### 5.2 大屏端

大屏作业范围应由服务端根据绑定关系计算，客户端不得从个人选班拼接：

```text
大屏作业范围
= 绑定的行政班工作区
+ 当前学期、当前年级中，科目规则为 COURSE_GROUP，
  且 sourceClasses 包含该行政班的所有启用走班工作区
```

由此得到：

- 一、二班全科随行政班时，大屏只加载行政班工作区；
- 三至七/八班存在走班时，大屏加载本班行政班和所有与本班有关的走班；
- 一个大屏可以看到本班学生分散参加的多个同科走班；
- 不会看到来源班级不含本班的其他走班。

### 5.3 信息量过大时的展示

大屏展示所有相关走班，但卡片必须清楚标出目标教学班。默认按“截止时间 / 优先级 / 发布时间”排序，并提供科目或教学班筛选。筛选只改变当前展示，不改变大屏有权接收的完整范围。

## 6. 大屏专用作业流 API

建议增加需要大屏令牌的接口：

```http
GET /api/v2/classroom-screens/feed
```

服务端流程：

1. 验证 `X-Classworks-Screen-Token`；
2. 读取绑定行政班；
3. 计算该行政班允许的大屏工作区；
4. 调用现有发布流查询逻辑；
5. 返回 `items`、`generatedAt`、`nextTransitionAt` 和实际工作区摘要。

这样可以避免客户端传入错误或过期的工作区 ID，也能保证大屏展示范围与大屏录入权限使用同一套规则。

`GET /classroom-screens/session` 仍返回绑定信息和可写目标，用于录入表单；其走班查询必须增加 `sourceClasses.some(administrativeClassId = 当前绑定行政班)` 条件。

建议在后端抽取统一函数，例如 `resolveClassroomScreenWorkspaceIds(binding)`，供以下功能共同使用：

- 大屏会话目标；
- 大屏作业流；
- 大屏新建、修改与恢复权限校验；
- Socket.IO 工作区订阅列表。

## 7. 前端状态与实时同步改造

Pinia 状态增加明确的作业流受众：

```js
feedAudience: "student" | "screen"
```

建议将当前 `loadFeed()` 拆为：

- `loadStudentFeed()`：使用 `selectedWorkspaceIds` 调公共学生作业流；
- `loadScreenFeed()`：调用大屏专用作业流接口；
- `loadActiveFeed()`：根据 `feedAudience` 分发，供刷新、定时器和实时事件统一调用。

实时层同步调整：

- 学生模式订阅个人选择的工作区；
- 大屏模式订阅服务端返回的大屏工作区；
- 模式或学生选班变化时，先退出旧房间，再加入新房间；
- 发布创建、更新、撤回、认证和恢复事件统一调用 `loadActiveFeed()`；
- `nextTransitionAt` 定时刷新也必须调用 `loadActiveFeed()`，不能固定回到学生流；
- 五分钟兜底轮询只刷新当前受众。

切换过程中保留上一屏内容并显示轻量刷新状态，避免大屏出现整页闪白。

## 8. 大屏布局设计

### 8.1 页面结构

大屏模式建议使用以下结构：

1. 紧凑顶栏：品牌、绑定班级、当前时间、模式入口；
2. 操作栏：科目/教学班筛选、显示设置、课堂工具、大屏录入、刷新；
3. 作业卡片网格：优先占用可视区域；
4. 状态提示：网络离线、数据过期、绑定失效等采用不遮挡内容的提示条。

学生端当前较大的“选班摘要”不应在大屏复用。大屏行政班已经固定，只需在紧凑顶栏显示绑定名称。

### 8.2 字体缩放

大屏提供 90% 至 200% 的作业正文字号缩放，步长 10%，默认建议为 130%。缩放只作用于作业正文，不改变教师端、学生端以及卡片的结构信息：

```css
--screen-font-scale: 1.3;
```

科目名、教学班、认证状态、优先级、作业标题、发布时间和操作按钮保持正常字号。自动列数仍参考正文字号计算最小卡片宽度，避免正文放大后列宽过窄。

### 8.3 空间密度

提供两档：

- **紧凑**（大屏默认）：减少卡片内边距、标题栏高度、标签间距和页面上下留白；
- **舒适**：保留较宽松间距，适合触摸操作或作业数量较少时。

“字体更大”和“空间更紧凑”应能同时启用：正文易读，但非内容区域少占空间。

### 8.4 列数与卡片

提供“自动 / 1 列 / 2 列 / 3 列”，默认自动。自动列数根据容器宽度与字体比例计算：字体越大，允许的最小卡片宽度越大，避免强行三列导致每行文字过短。

卡片建议：

- 正文保留换行，不截断；
- 科目、目标教学班、认证状态放在同一紧凑标题区；
- 截止时间临近或已过期使用颜色与图标双重提示；
- “历史版本 / 修改”等低频动作放入卡片菜单，减少常驻按钮；
- 未认证卡片与已认证卡片保持明显但不过度刺眼的差别。

### 8.5 时间卡片

大屏固定展示一张紧凑时间卡片，点击后进入全屏时钟。全屏时钟将时分与秒分开排版，秒使用较小字号和独立间距，避免数字拥挤。

## 9. 大屏显示设置

第一版设置项：

| 设置 | 值 | 默认值 |
| --- | --- | --- |
| 作业正文字号 | 90%～200%，步长 10% | 130% |
| 空间密度 | 紧凑 / 舒适 | 紧凑 |
| 卡片列数 | 自动 / 1 / 2 / 3 | 自动 |
| 展示次要信息 | 开 / 关 | 开 |

设置按大屏绑定 ID 保存在当前浏览器：

```text
classworks-v2-screen-display:<bindingId>
```

采用本地保存的原因：

- 字体大小取决于教室屏幕尺寸和观看距离，不是学校或行政班的统一业务数据；
- 同一行政班更换设备时可分别调节；
- 设置不需要网络即可生效。

读取时要做字段白名单和数值范围校验；异常或旧版本数据回退到默认值。设置面板提供“恢复默认”。后续确有远程统一配置需求时，再增加管理员下发默认值，本地值仍可覆盖。

建议提供快捷操作：

- `Ctrl` + `+`：放大；
- `Ctrl` + `-`：缩小；
- `Ctrl` + `0`：恢复默认字号；
- `F11`：沿用浏览器全屏行为。

不要拦截输入框内的普通按键；快捷键只在大屏模式且焦点不在输入控件时处理。

## 10. 组件拆分建议

避免继续扩大 `ClassworksHome.vue`，本阶段建议拆分：

```text
ClassworksHome.vue
├─ ClassworksModeSwitcher.vue
├─ StudentHomeworkView.vue
├─ TeacherWorkspaceView.vue
└─ ClassroomScreenView.vue
   ├─ ClassroomScreenToolbar.vue
   ├─ HomeworkFeedGrid.vue
   └─ ScreenDisplaySettingsDialog.vue
```

`HomeworkFeedGrid.vue` 可以由学生端和大屏端复用，但通过明确 props 控制：

- `audience`；
- `fontScale`；
- `density`；
- `columns`；
- `showActions`；
- `showSecondaryMetadata`。

组件内部不得自行读取学生选班或大屏令牌，数据范围由上层视图和 Store 决定。

教师端可以暂时保留现有实现，只先从主页中移动出去，降低一次改造的风险。

## 11. 响应式与可访问性要求

### 学生端

- 360px 宽度下单列显示，无水平滚动；
- 选班、刷新和内容浏览可用触摸完成；
- 作业正文不因长英文、URL 或连续字符撑破卡片。

### 教师端

- 发布表单在笔记本宽度下可完整操作；
- 登录、PIN 修改和作业编辑的错误提示保留；
- 教师模式不继承大屏字体缩放。

### 大屏端

- 1920×1080、1366×768 两种典型分辨率重点验收；
- 在 150% 字体、紧凑模式下，按钮和卡片不得重叠；
- 200% 字体时允许减少列数或增加页面滚动，但不能裁切正文；
- 认证状态不能只依赖颜色，要同时有图标和文字；
- 网络断开时保留最后一次成功内容，并标注更新时间。

## 12. 分阶段实施

### 阶段 A：数据边界修正

- 后端抽取大屏工作区解析函数；
- 大屏走班目标按 `sourceClasses` 限定；
- 新增大屏专用作业流接口；
- 为一、二班全科随班、普通班多走班、无关走班排除编写服务测试。

完成标准：大屏作业范围不再依赖浏览器个人选班，且不会返回与绑定行政班无关的走班。

### 阶段 B：前端三模式与状态流

- 引入 `student / teacher / screen` 三态；
- 有效绑定默认进入大屏模式；
- 已绑定设备隐藏学生端和教师端入口；
- 拆分学生流和大屏流；
- 修改刷新、定时刷新和实时订阅，使其跟随当前受众；
- 大屏模式隐藏“修改选班”。

完成标准：刷新页面和切换模式后均加载正确作业，Socket.IO 更新不会把大屏错误切回学生流。

### 阶段 C：大屏布局与显示设置

- 建立紧凑大屏工具栏和卡片网格；
- 实现作业正文字号、密度、列数和紧凑时间卡片；
- 按绑定 ID 本地持久化；
- 增加键盘快捷键和恢复默认。

完成标准：设置刷新后保留；90%～200% 范围内没有卡片或按钮堆叠；后排可通过现场调整获得合适字号。

### 阶段 D：组件清理与回归

- 从 `ClassworksHome.vue` 拆出三种视图和共享作业网格；
- 清理学生视图中残留的大屏专用条件分支；
- 补充单元测试、API 集成测试和浏览器端到端测试；
- 更新主页切换、部署和管理员操作文档。

完成标准：生产构建通过，既有教师发布/认证/历史恢复、大屏录入/恢复、学生选班均无回归。

## 13. 测试与验收清单

### 13.1 组织结构用例

- 一班全科 `ADMIN_CLASS`：学生不显示小科走班选择；一班大屏只加载一班行政班空间。
- 二班全科 `ADMIN_CLASS`：行为与一班一致。
- 三班物理为 `COURSE_GROUP`，来源包含物理 A1、A2：三班学生只看本人所选的一个班，三班大屏同时看到 A1、A2。
- 物理 A3 来源不含三班：三班大屏不可见、不可录入、不可修改 A3 作业。
- 四至七/八班按实际后台配置重复验证，不依赖班级名称或序号。

### 13.2 身份与模式用例

- 未绑定、未登录浏览器默认学生端；
- 教师登录后教师端发布、认证和修改正常；
- 已绑定浏览器刷新后默认大屏端；
- 停用绑定后，大屏接口返回 401/409，前端撤销大屏能力并提示重新绑定；
- 已绑定大屏不显示学生端或教师端入口；停用绑定后恢复普通浏览器入口。

### 13.3 显示用例

- 1366×768 和 1920×1080 下测试 90%、130%、150%、200%；
- 紧凑/舒适、自动/1/2/3 列组合无内容堆叠；
- 长标题、多行正文、无标题、多个标签、过期截止时间均正确换行；
- 显示设置只影响当前大屏绑定，不影响学生端、教师端或另一绑定。

### 13.4 实时与容错用例

- 教师新发布、认证、修改、撤回后大屏自动刷新；
- 大屏录入后学生端和教师端收到更新；
- 模式切换后旧工作区事件不触发错误作业流；
- 断网后仍显示缓存内容，恢复网络后自动同步；
- `nextTransitionAt` 到达后，定时发布和截止状态在当前模式正确变化。

## 14. 风险与控制

### 大屏信息过多

一个行政班可能关联多个同科走班。通过教学班标签、筛选、排序和自动列数控制信息密度，不通过错误地只选一个走班来减少内容。

### 三模式共享一个 Store 导致串流

使用显式 `feedAudience` 和统一 `loadActiveFeed()`，并集中管理房间进入/退出。避免各组件自行调用旧的 `loadFeed()`。

### 本地显示设置损坏

读取时校验版本、枚举和范围，任何异常都回退默认设置；提供一键恢复默认。

### 学校分班尚未确定

业务逻辑仅依赖学期、科目规则和 `sourceClasses`，不硬编码“一至八班”或具体 A/B 班名称。正式名单确定后只需通过初始化/管理功能录入组织数据，再运行组织结构验收用例。

### 大屏令牌被复制

当前阶段仍以开箱即用为优先。大屏接口必须只允许绑定班级范围内的操作；管理员可以停用并重新绑定设备，使旧令牌立即失效。后续如有实际滥用，再增加令牌轮换或设备二次确认，不作为本阶段阻塞项。

## 15. 本阶段明确不做

- 不创建三套独立前端或三个域名；
- 不要求学生、教师使用邮箱；
- 不把显示设置同步到服务器；
- 不在代码中固定学校最终班级数量和走班名称；
- 不迁移 Classworks 官方服务器上的旧 UUID 作业数据；
- 不在本阶段删除随机点名和考试看板，只保持它们位于大屏课堂工具中，后续单独评估删除。

## 16. 推荐实施顺序

先完成阶段 A 和 B，确保大屏看到的是正确作业；再完成阶段 C 改善后排可读性；最后进行阶段 D 的组件清理和全量回归。

正确的数据范围优先于界面美化。只有服务端能够稳定回答“这台行政班大屏应该看到哪些工作区”，字体、密度和卡片布局的改造才建立在可靠基础上。
