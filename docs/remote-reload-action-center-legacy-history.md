# 远程重载、待处理中心与跨版本噪声历史

2026-09-06。本次仅修改本地前后端代码、测试和说明；未推送、未部署，没有修改 `deploy/agent/server.js`，没有新增服务器数据库结构迁移。

## 远程重载

- 大屏作业录入窗口打开、作业提交或队列补传进行中时，暂缓执行远程重载。忙碌时不确认指令，由现有心跳再次获取，继续遵守后端指令有效期。
- 确认响应期间或 300 毫秒倒计时内又开始编辑时，重载继续等待；切换绑定、令牌或停止同步会取消旧会话的定时器。
- 草稿写入失败会显示警告并保留录入窗口，关闭时重试保存；存储仍不可用时不关闭。正常联网提交仍可进行。
- 保护注册在组件生命周期和实际提交操作上。提交期间即使组件关闭，提交操作结束前仍阻止重载；持久化后的离线队列本身不阻止空闲重载。

## 待处理中心

原接口每页返回 20 条，但先加载全部候选作业和最近认证快照。现在使用数据库查询计算权限、分类、优先顺序和汇总，先选出当前页 ID，再加载这一页的正文和快照。

- 保留“每个目标都必须有对应学科权限或完整管理权限”的规则；学校、班级、科目、原因筛选以及汇总语义不变。
- 保留原因、逾期、即将到期、优先级、修改时间排序；同时间追加 ID 排序，保证静态数据跨页稳定。
- 汇总、页 ID 和详细快照在同一 Repeatable Read 事务内读取，防止同一响应内读取不同数据库版本。
- 接口参数和返回结构不变；空页仍返回正确总数与汇总。无需前后端同步上线。

真实 PostgreSQL 测试种入 1,200 条合成作业，其中 1,022 条属于默认待处理结果；逐项比较管理员、学科教师、原因、科目、班级、未知筛选、第二页和末页之外的结果及差异字段。

| 默认第一页测量 | 原实现 | 新实现 |
| --- | ---: | ---: |
| 加载完整详情的记录数 | 1,022 | 20 |
| 加载记录的 JSON 序列化大小 | 18,446,454 字节 | 521,053 字节 |
| 本次调用耗时 | 148.9 ms | 61.8 ms |

这是本机、合成数据的单次测量，计时包含测试中计算记录体积的成本，不代表线上延迟或内存占用百分比。数据库仍需扫描匹配记录以生成准确汇总，但不再把页外正文和快照加载到 Node.js。

## 新旧页面并存

- 新版读取或追加历史时检查旧存储源是否变化，有变化才合并；按 ID 写入，避免重复记录。
- 不再在迁入提交后自动删除旧存储键：IndexedDB 提交与 localStorage 删除不是同一个事务，删除可能覆盖旧页面刚写入的数据。因此保留旧格式的有界副本，代价是继续占用既有 localStorage 空间。
- 清空时在 IndexedDB 事务内同时记录清空时间、已删除 ID 并删除统计；旧页面重写自己的缓存时，已清空片段不会重新出现，清空后产生的新片段仍会导入。
- 已经打开的旧格式页面无需立刻刷新才能保住后续记录。旧版仍不能读取新版仅存于 IndexedDB 的新记录；这次没有增加反向同步。
- 已被之前运行的代码删除的数据无法凭空恢复。

真实 Chromium 验证包括两个同时打开的页面、重复导入、清空后旧页回写、迁入期间源数据变化、写入失败重试、容量与过期清理。复测 5,000 条历史：旧同步保存中位 8.4 ms，当前增量保存完成时间中位 0.5 ms，首次导入约 128.8 ms；均为开发机数据。
