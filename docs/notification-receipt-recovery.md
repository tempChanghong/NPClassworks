# 通知回执跨刷新恢复（2026-09-07）

原队列仅存在内存；若重载后 feed 不再包含通知，无法仅凭本地确认标记恢复待发回执。新增回归先复现重建队列后待发数由预期 1 变成 0，再验证持久化后的恢复和补发。

## 行为

- 队列按后端地址、绑定 ID 和 credentialVersion 隔离，只保存通知 ID、revision、展示/确认状态和永久错误状态，不保存令牌或通知正文。
- 离线入队立即尝试保存；组件重建时读取，联网后即使当前 feed 没有原通知，也会恢复发送。成功响应后删除已提交批次，同一通知保留较新的版本，确认状态不会被同版本展示回执降级。
- 每批最多 100 条，与服务端处理上限一致；成功后继续处理剩余积压，不能把服务端未处理的尾部当作已发送。
- 读取失败或数据损坏时不覆盖原记录；保留本次已知内存记录，重试读取成功后合并。写入失败保留内存状态并在大屏显示警告和重试入口。
- 401/403 等不可自动恢复的状态随队列保存，刷新不会重新开启无限重试。不同绑定或凭据版本不会接管原队列；旧在途响应在队列销毁后不能删除新队列的数据。

后端原规则不变：旧版、已撤回或不再属于该大屏投放范围的通知回执会被忽略。队列补发不等于服务端接受过期确认，更不会把旧版确认算给新版。HTTP 成功表示该批处理结束，服务端忽略的无效回执也不继续重试。

## 跨标签页修复（2026-09-10）

- 保留现有 version 1 主队列格式。读取、合并和清理都在同一作用域的 Web Locks 锁内完成；网络发送不持锁，其他页面仍可记录新回执。
- 每次新增回执先同步写入独立、不可变的 `:staged:` 临时记录，再在锁内合并到主队列；主队列写入成功后才删除已合并的临时记录。点击确认后立刻刷新，或等待锁时关闭页面，新的页面仍可恢复这些记录。
- 上传完成后重新读取最新队列，只删除与本批 revision、展示及确认状态完全一致的记录，保留其他标签页新增或升级的回执。旧页面同步和退出时不写回整份旧内存快照。
- 监听本作用域的 storage 事件，使其他标签页及时同步队列状态；本机新增与已完成批次的清理状态在读写失败时保留，恢复后重试。无法获得跨标签页锁时显示存储异常，不退回不安全的整份覆盖写入。
- 多标签页一致性需要各标签页都更新到包含此修复的前端；旧代码不使用锁，仍可能覆盖主队列。旧绑定的待处理存储不自动转移或静默淘汰；本机容量不足会显示存储异常。

当前调用方可等待 `enqueue()` 返回的 Promise，确认本次合并已完成。界面在等待期间保留同步写入的本地确认标记，完成后再更新确认状态，避免快速刷新重复弹窗。

跨标签页修复验证：448 项前端单元测试通过，其中回执队列 21 项；13 项相关 Chromium 浏览器场景通过，包含两个标签页同时离线确认、真实 Web Lock 被占用时关闭页面、无原通知 feed 的恢复补发、立即刷新与 105 条确认回归。Lint、生产构建和 PWA 校验通过。本次未改后端或服务器部署配置。
