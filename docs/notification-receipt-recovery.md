# 通知回执跨刷新恢复（2026-09-07）

原队列仅存在内存；若重载后 feed 不再包含通知，无法仅凭本地确认标记恢复待发回执。新增回归先复现重建队列后待发数由预期 1 变成 0，再验证持久化后的恢复和补发。

## 行为

- 队列按后端地址、绑定 ID 和 credentialVersion 隔离，只保存通知 ID、revision、展示/确认状态和永久错误状态，不保存令牌或通知正文。
- 离线入队立即尝试保存；组件重建时读取，联网后即使当前 feed 没有原通知，也会恢复发送。成功响应后删除已提交批次，同一通知保留较新的版本，确认状态不会被同版本展示回执降级。
- 每批最多 100 条，与服务端处理上限一致；成功后继续处理剩余积压，不能把服务端未处理的尾部当作已发送。
- 读取失败或数据损坏时不覆盖原记录；保留本次已知内存记录，重试读取成功后合并。写入失败保留内存状态并在大屏显示警告和重试入口。
- 401/403 等不可自动恢复的状态随队列保存，刷新不会重新开启无限重试。不同绑定或凭据版本不会接管原队列；旧在途响应在队列销毁后不能删除新队列的数据。

后端原规则不变：旧版、已撤回或不再属于该大屏投放范围的通知回执会被忽略。队列补发不等于服务端接受过期确认，更不会把旧版确认算给新版。HTTP 成功表示该批处理结束，服务端忽略的无效回执也不继续重试。

本次未实现跨标签页事务或互斥，不宣称多个标签页同时改写同一绑定队列已获得一致性保证。旧绑定的待处理存储不自动转移或静默淘汰；本机容量不足会显示存储异常。

## 验证

- 队列 14 项测试通过：含刷新恢复、作用域隔离、永久错误保持、读写失败恢复、205 条分批发送、版本变更及销毁后的晚响应。
- 真实 Chromium + 生产 PWA 浏览器测试通过：离线点击“知道了”、Service Worker 重载、通知离开服务端 feed 后恢复发送。该浏览器场景仍使用原有内存测试 API；不是 PostgreSQL 端到端实测。教师发布到大屏的浏览器回归也通过。
- 前端普通测试共 300 项通过；跨仓契约 2 项通过，包含真实后端 Socket 实现；Lint 通过。
