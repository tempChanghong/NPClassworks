# v1.1.0 发布后验收

本轮补充真实旧版升级、名单管理全链路及性能基线。测试仅使用本机回环地址、测试账号和可丢弃 PostgreSQL，不访问生产数据，不修改部署代理。

## 真实版本升级

运行 `pnpm test:upgrade`。需先安装两仓依赖、Chromium，并启动 Docker；依赖与数据库配置沿用[全链路说明](./fullstack-smoke-tests.md)。

脚本锁定以下源码，而不是给同一份当前代码换两个标记：

| 阶段 | 发布标签 | 完整提交 |
| --- | --- | --- |
| 升级前 | v1.0.1 | `6194a954c300165325b897b7d7d56e72880970bd` |
| 升级后 | v1.1.0 | `a43899301a6b6b94956a6d209c89f2a8b12a5675` |

注意：v1.0.1 标签里的 package.json 实际仍写着 1.0.0。保留该历史源码，使用完整提交号判定升级来源；测试不修正旧标签，也不把包版本字符串当成源码证明。

脚本通过独立 Git worktree、各版本自己的锁文件和依赖构建。只在 HTML 添加提交号证据，不替换应用 JavaScript、离线存储或 Service Worker。旧、新构建放在 `dist-e2e/release-upgrade/`，可重复使用；已有 checkout 的提交或已跟踪源码被修改时拒绝继续。标签对象尚未获取时先运行 `git fetch origin tag v1.0.1 tag v1.1.0`。

验收步骤：

1. 旧版页面实际修改浅色主题，断网录入待上传作业，并另存一份未提交草稿。
2. 保持同一浏览器存储，切换静态站点到新版；模拟独立 API 暂时不可达，通过真实 Service Worker 安装、激活和页面的“立即刷新”按钮更新。
3. 在断网状态加载新版，确认响应来自 Service Worker，核对主题、绑定凭据、原请求 ID 和草稿内容。
4. 恢复真实 API 后补传，再通过真实 HTTP 重放原请求，确认数据库只有一条作业、一份修订。
5. 新版收到次要通知，检查等级和不弹窗选项。

接口成功响应来自真实后端和 PostgreSQL；网络故障通过浏览器断网或请求中止模拟。此场景不模拟旧后端数据库升级，也不覆盖真实反向代理缓存或物理设备休眠。

手动 GitHub Actions 工作流为 `Released PWA upgrade acceptance (manual)`，默认配合后端 v1.1.0；只验证，不部署。输出保留旧、新前端提交信息、实际后端提交及失败 trace。当前名单全链路用例自动随已有生产部署检查执行。

## 名单全链路

运行 `pnpm test:e2e:fullstack`，或使用 `pnpm test:e2e:fullstack roster.spec.js` 定向验证。

新增场景通过管理员页面修改姓名、移出学生并导入新学生；大屏在此之前打开名单编辑器并保留输入。验证：

- 管理员保存真正写入数据库，保留已有学生 ID；移出的学生停用，原历史考勤内容不变。
- 大屏收到实际 `classroom.roster.updated` Socket 事件，当前编辑草稿保留。
- 大屏以旧版本保存返回 409，未覆盖数据、未产生第二条成功名单审计。
- 管理员成功写入的审计包含完整前后名单。
- 大屏主动重新加载后看到已保存的新名单。

该场景模拟双方同时开始编辑、随后先后提交。数据库事务锁的同时写入竞争另由后端数据库测试覆盖，不能把本用例表述为精确同时进入两笔事务。

## 性能基线与实机验收

运行 `pnpm test:performance`。Windows 上可用实际安装的 Edge：

```powershell
$env:PERFORMANCE_BROWSER_CHANNEL = 'msedge'
pnpm test:performance
```

脚本分别采样正常 CPU 和 4 倍降速，使用真实页面、API、数据库和 AudioWorklet；音频来自 Chromium 的合成设备，不启用实际麦克风。负载为 30 条长作业、20 条次要通知、一个已加载的预设背景和手动噪声监测，再反复打开关闭放大页面。

输出 `test-results/performance/**/measurements.json`，记录系统、CPU、内存、浏览器版本、操作耗时、主线程长任务、JS 堆、DOM 节点和监听器数量。测量前预热弹窗，前后另做 GC 后快照。这里的操作耗时包含 Playwright 驱动、元素可交互等待及动画，不是 INP；JS 堆不是整个浏览器进程内存。短时结果不证明无内存泄漏，降速不模拟低内存、旧显卡或真实休眠。

当前用户提供的学校大屏配置为 Windows 10 / Microsoft Edge / 8 GB / Intel i7-1065G7。尚未在这台物理大屏上运行；开发电脑测量不能替代该结果，也不能代表全国一体机配置。

后续物理设备验收记录表：

| 场景 | 记录内容 |
| --- | --- |
| 冷启动与日常启动 | 浏览器版本、屏幕分辨率/缩放、网络状态、首份完整作业可见时间 |
| 长正文与多条通知 | 滚动、放大、折叠通知是否可正常操作；是否出现内容截断或持续无响应 |
| 预设背景与手动监测同时运行 | 输入设备、是否持续采样、应用退出监测页后的状态、浏览器进程 CPU/内存 |
| 连续使用两小时 | 开始、30 分钟、1 小时、2 小时的进程内存与 CPU，是否持续增长；不记录学生内容 |
| 休眠与恢复 | 待机前后版本、恢复联网和内容更新时间，是否重复弹窗/播放、麦克风能否恢复 |
| 更低配置设备 | 实际设备型号与相同场景结果；单独归档，避免用开发机降速数据推算 |

性能采样应单独运行，避免同时构建或执行其他浏览器测试。先形成可重复基线，再设置适合学校设备的门槛。

## 本轮实测结果

- 真实后端、隔离 PostgreSQL 和浏览器全链路：9 项通过，包括新增名单场景。
- 真实发布版本升级：连续三次通过，分别约 6.2、30.8、7.0 秒。真实 Socket 长轮询期间，新 Worker 安装完成后可能继续等待旧请求结束；测试允许至多 60 秒自然激活，没有跳过安装、强制激活或清除存储。
- 前端普通测试 477 项及 Lint 通过。
- 本机 Edge 性能基线：正常速度和 4 倍 CPU 降速两档均完成，功能断言通过，音频采样在离开监测页后持续增加。

性能测量环境：Windows 内核版本 10.0.26200、Intel Core Ultra 9 275HX、31.4 GiB 可见内存、Edge 152.0.4191.66，headless 模式。原始数据见 [edge-performance.json](./reviews/2026-09-12-release-acceptance/edge-performance.json)。

| 指标 | 正常 CPU | 4 倍 CPU 降速 |
| --- | --- | --- |
| 放大操作自动化计时中位数（10 次） | 59 ms | 312 ms |
| 同项计时范围 | 54–73 ms | 281–365 ms |
| 采样窗口主线程长任务（超过 50 ms） | 0 | 30，最大 106 ms |
| GC 后 JS 堆，循环前 → 结束后 | 18.31 → 18.73 MiB | 18.43 → 18.71 MiB |
| DOM 节点，循环前 → 结束后 GC | 6012 → 5885 | 6010 → 5885 |
| 监听器，循环前 → 结束后 GC | 1581 → 1570 | 1581 → 1570 |

两档均未出现功能操作失败，结束后的节点和监听器数量没有高于开始值。这是一次短时样本；没有据此认定内存泄漏已被排除，也没有把上述计时设为所有设备的门槛。物理班级大屏的两小时、休眠唤醒及真实麦克风验收仍需在对应设备上完成。

以上状态只反映本地运行；未触发 GitHub Actions 或部署。
