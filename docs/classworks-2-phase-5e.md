# Classworks 2.0 第五阶段 E：账号与学期运维

本阶段补齐学校正式启用后最常用的运维入口。学校不需要教师邮箱；推荐继续使用“学校代码 + 短账号 + 个人 PIN”，OAuth 和全校通用密码仅作为初始化时可选的兼容模式保留。

## 已完成

- 教师可在新版作业板内修改自己的 PIN；修改成功后所有旧会话失效，需要重新登录。
- 学校 OWNER/ADMIN 可查看本校本地账号、创建第二管理员、重置教师 PIN、停用或重新启用账号。
- OWNER 可创建另一名 OWNER；ADMIN 只能创建 ADMIN，且系统不允许停用或注销最后一名 OWNER。
- “注销权限”是软注销：删除该账号在本校的成员关系和教学空间权限、撤销会话并禁用登录，但保留其历史作业和通知署名。
- 首次分配或重置后，可立即下载一次 CSV 凭据。服务端不保存明文 PIN，页面刷新后也无法重新导出旧 PIN。
- 学期运维可复制既有学期的行政班、走班教学空间、教师权限和未认领 OAuth 邀请；新学期默认是草稿。
- 学期可在草稿、启用和归档之间切换。启用新学期时，同校原启用学期自动归档。
- 管理员列表会显示本校所有学期，方便回看和复制已归档学期。

## OWNER 应急恢复

登录页提供折叠的“OWNER 应急恢复”入口，需要同时提供：

1. 学校代码；
2. OWNER 短账号；
3. 新 PIN；
4. 服务器环境变量 `BOOTSTRAP_SETUP_KEY`。

这个入口用于 OWNER 忘记 PIN 或被锁定时的离线救援。恢复后该 OWNER 的所有既有会话会被撤销。正式部署后应把 `BOOTSTRAP_SETUP_KEY` 当作服务器管理密钥保存，不应发给普通教师或学生。

## 推荐的开学操作顺序

1. 第一位 OWNER 完成学校初始化后，立即创建第二位管理员并分别保管账号。
2. 在“学期运维”中从上一学期复制结构，先保持草稿状态。
3. 核对一、二班小科仍随行政班，其他班走班空间与教师分配正确。
4. 导入或调整教师账号，现场发放短账号和初始 PIN，提醒教师首次登录后修改。
5. 用测试学生选择行政班和走班，检查可见作业。
6. 确认无误后启用新学期；旧学期会自动归档。

## 明确不做的迁移

本项目将部署到新购买的服务器，原 Classworks 使用官方服务器，因此不存在可直接访问的旧 UUID/KV 作业数据。本次正式上线不设计、不执行旧 UUID 作业迁移，也不把它列为部署阻塞项。

旧 UUID/KV 代码暂时保留，是为了降低魔改过程中回归旧首页功能的风险，并不代表上线前还需要搬运官方服务器数据。后续确认全校只使用 Classworks 2.0 后，可另开阶段清理旧入口和兼容代码。

## 仍需在服务器确定后完成

- 购买并初始化云服务器，配置 `cs.newfires.top` 的 DNS、HTTPS、备份与监控。
- 用学校最终名单替换示例组织数据，尤其核对三至八班的选科与实际走班代码。
- 正式上线前进行一次初始化、教师登录、学生选班、发布、学期切换和 OWNER 恢复演练。
