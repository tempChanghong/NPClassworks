# 核对清单发布时间边界（2026-09-14）

## 已确认的问题

“明日要交与需带”用发起请求时保存的时间判断返回记录是否已发布。当请求期间到达定时发布时间，服务器已返回该记录，前端仍认为它尚未发布，将其静默过滤。例如 12:00:00 发起查询、12:00:10 到发布时间、12:00:20 返回，清单却显示明日要交 0 项。

问题涉及明日要交、今日未设截止时间的作业，以及明日需带物品。它发生在服务器已返回记录后的客户端过滤阶段，不是服务器漏查。

## 修复及验证

等待全部响应完成后，统一读取当前时间判断三类内容的发布可见性。日期查询范围仍按发起时的日期计算；原有跨日失效保护保留。没有放开尚未发布内容的过滤。

- 修复前：新单元用例得到空数组；学生和大屏的两项浏览器用例均复现“明日要交 0 项”。
- 单元用例验证三类刚发布内容均保留，尚未到发布时间的内容仍被排除。
- 浏览器通过可控时间模拟请求期间到达发布时间，同时回归查询失败、版本混用、关闭后旧响应晚到和跨午夜失效。

本次仅修改前端工具函数及测试，不涉及后端、数据库迁移或部署代理；未提交、推送或部署。测试采用可控浏览器时间和接口夹具，不声称覆盖服务器与客户端时钟偏差。
