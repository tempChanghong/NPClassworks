# 通知回执、诊断写入和性能采样

## 通知回执

- 离线时保留内存中的待处理回执，不发送请求，并取消已有重试定时器。
- 无 HTTP 响应的网络故障、408、429 和服务端故障按 10、20、40、80、160、300 秒退避，之后保持最多每 5 分钟一次。成功后重置退避。
- 恢复联网立即尝试一次；已有请求执行中时不会并发发送。新增回执不会绕过退避。
- 其他 4xx 停止当前队列的自动发送，保留待处理项；网络恢复不会解除停止状态。诊断快照 `notificationDelivery` 提供 `blockedStatus`、`pendingCount` 等信息，事件 `NOTIFICATION_DELIVERY_BLOCKED` 记录原因，不记录通知正文或令牌。
- 权限或数据问题处理后，重新载入页面或重新绑定会创建新队列，当前展示通知根据本地确认记录重新生成回执。这里没有新增跨刷新持久化队列，刷新后的重建范围仍是当前通知。
- 同一修订的已确认回执不会被后到的“仅展示”回执降级。销毁旧队列后，其异步结果不能重新安排重试或更新诊断状态。

## 诊断快照

快照立即脱敏并保留在内存，按名称合并最新值，从第一次更新起 1 秒内批量读写一次；持续更新不会无限推迟保存。读取和导出诊断会包含尚未批量写入的快照。

事件仍同步保存，并同时保存已有待写快照。页面隐藏、离开时主动保存；清空诊断也取消待写数据，避免旧计时器将其恢复。存储不可访问或容量不足时，不让诊断异常影响业务，也不循环重试诊断写入。

取舍：进程被强制结束、没有生命周期事件时，最近一个批量窗口内的普通快照可能丢失。事件没有新增延迟，存储写入本身仍可能失败。该缓冲与离线作业队列无关。

### 2026-09-05 本机基准

在本地 Chromium 的真实 localStorage 中预置 150 条诊断事件，然后连续记录同名快照 1,000 次。分别将修改前 HEAD 与当前实现打包，使用相同数据各测 5 次；修改后计时包含最后一次批量保存。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 每轮存储读取次数 | 1,000 | 1 |
| 每轮存储写入次数 | 1,000 | 1 |
| 5 次耗时中位数 | 162.3 ms | 1.8 ms |
| 耗时范围 | 151.8–178.5 ms | 1.3–2.1 ms |

这是集中更新基准，不代表日常页面总耗时或低配大屏的实测收益。更新间隔超过批量窗口时仍会分别保存。1 秒窗口在减少密集写入和诊断新鲜度之间取舍。

## 性能采样

- 后台不累计事件循环延迟或长任务，暂停次数与时长记录在 `background`。
- `visibilitychange`、`freeze/resume`、`pagehide/pageshow` 驱动采样暂停和基准重置。恢复后延迟交付的旧后台长任务按开始时间排除。
- 没有生命周期事件，但采样间隔超过 2 分钟时，单列为 `samplingGaps`。同时比较单调时钟和墙钟，兼容休眠期间单调时钟停止或继续运行的情况。
- 超长间隔的原因无法可靠区分休眠、浏览器暂停和时钟调整，所以不直接称为卡顿或休眠。正常前台延迟仍计入 `eventLoopDrift`，PerformanceObserver 实际报告的前台长任务仍独立计入 `longTasks`。

- 前端 179 项测试通过。新增覆盖退避上限、永久错误停止、离线恢复、并发确认、销毁后迟到响应、批量保存、立即保存关键错误、清空后不恢复、存储失败，以及性能采样生命周期。
- 用可控时钟模拟 24 小时后台/恢复循环及两种休眠时钟行为；这不是实际运行 24 小时的硬件休眠测试。
- 7 项 Chromium 端到端测试通过，包含教师发布与 Socket.IO 更新、离线刷新与补传、PWA 跨版本升级、冲突确认和反复冻结恢复。
- Lint、生产构建、PWA 构建校验通过。
