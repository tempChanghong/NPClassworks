# 大屏布局方案 A

此目录保留独立交互原型 `screen-layout.html`，用于评审空间分配。方案随后已接入正式 Vue 页面，具体行为见 `../screen-layout.md`。原型仍可直接用浏览器打开，无需安装依赖或连接后端，所有内容都是示例数据。

## 布局调整

- 顶部集中班级、时间、同步摘要和操作入口，保留“录入作业”和“抄写模式”；低频操作收入“更多”。
- 保留原有底部快捷栏：前一天、今天、后一天、通知中心、课堂工具、显示设置、刷新和录入作业。顶部“更多”不替代这些快捷入口。原型在右下方展示，窄屏居中换行；页面末尾按快捷栏实际高度预留空间，滚到底部时可完整查看最后一张卡片。正式接入继续保留现有左/中/右位置设置、通知角标和加载状态。
- 将日期、科目录入状态和明日需带摘要合并成一行，状态及需带详情可展开。仍区分“未录入”“明确无作业”和“待教师确认”。
- 通知收起时保留摘要；模拟新通知会强制展开并弹窗。紧急通知另有醒目横条。正式接入须沿用现有通知等级、弹窗偏好和确认逻辑。
- 日常作业用三列卡片；长作业在宽屏占较宽区域，其他作业纵向排列，避免普通网格被长卡片撑出空白。较窄屏幕改为顺序排列。
- 正文默认 30px，可在原型中调整到 26–40px；不因作业数量增加而自动缩小，不截断正文，保留全文放大。内容多时允许整页滚动。

## 如何查看

顶部可切换“日常作业”“长作业”“通知较多”，以及深浅色和字号。可检查通知展开、科目状态、需带详情、放大和简化的抄写预览。

“更多”菜单与录入按钮仅展示入口位置，不执行正式功能。抄写预览仅演示隐藏辅助区域的效果，不代表已实现或替换现有分页抄写功能。

## 已验证与限制

- 用 Chromium 检查 1920×1080、1366×768、540×900 的日常场景，无页面横向溢出；1920 宽度还检查了长作业和多通知场景。
- 验证长正文及放大内容完整、通知收起后新通知强制展开并弹窗、状态弹窗及抄写预览退出，未发现浏览器脚本错误。
- 日常场景在 1920×1080、默认字号下可完整展示六科示例。作业区起点为页面第 303px，包含仅原型存在的顶部控制条。此数据不是与正式页面的性能或空间收益对比。
- 长作业和多通知场景仍可能需要滚动。这一轮没有证明任意数量或长度的内容能在一屏放下。
- 尚未在班级大屏和教室后排验收可读性，也未连接真实权限、离线队列、Socket.IO 或通知声音。

正式接入时需保留现有日期切换、走班标识、同步异常和待上传状态、作业更正提醒、通知确认、需带物品及复制/打印能力，逐项回归；不能以此原型的固定数据和入口代替业务流程。长卡片的识别目前仅用示例字符数，正式实现应结合实际排版尺寸，并避免实时更新使科目位置频繁跳动。
