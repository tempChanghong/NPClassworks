## 已修复的问题

### 保存等待期间更换绑定或凭证

位置：`src/stores/classworksV2/screenSessionActions.js` 的 `saveScreenPublication`。

触发：已确认文字并点击保存，请求等待期间替换班级绑定、凭证版本或令牌。旧请求随后失败，原先会调用当前绑定的离线入队；旧请求随后成功，则会继续发出保存成功事件，关闭录入并清除原草稿。

修复：保存操作固定绑定、凭证版本和令牌，在请求完成、内容刷新完成和失败回退前核对。失效回调不能继续入队或报告当前窗口已保存；保留原输入，提示回原绑定核对。旧请求可能已经成功，所以不把这类结果简单说成“服务器未保存”。

证据：四个 Vue/Axios 交互反例修前全部失败，修后通过。真实 KV 额外验证有效令牌在请求中途更换后，成功响应和已提交但响应丢失两个分支均保留确认文字及本机草稿，没有额外队列或重复修订。

### 补传批次只检查绑定编号，没有固定凭证

位置：`src/stores/classworksV2/screenSyncActions.js` 的 `flushScreenPublicationQueue`、`retryScreenQueuedPublication`。

触发：第一项补传请求已发出，令牌先变化、绑定资料尚未刷新。原自动补传会继续用新令牌发送旧批次的后续项；原手动重试会根据旧回执移除队列项。

修复：自动与手动补传均固定本次令牌和凭证版本，失效后停止批次、保留未确认项及原请求编号；仅由仍拥有该同步操作的上下文结束“提交中”，不干扰新上下文。核对后恢复成功时，清除这一操作留下的暂停提示，不清除其他错误。

证据：令牌变化的自动、手动补传反例修前失败；新增四项覆盖令牌/凭证版本变化及后续恢复。真实 KV 验证“实际已提交 → 凭证变化 → 保留队列 → 用有效新凭证重新载入 → 相同请求编号补传”，最终只有一条作业、一版修订，界面没有卡在“正在同步”。

以上证明了请求或本机队列的归属错误，不代表 KV 已绕过权限检查，也不能据此认定学校现场发生过跨班落库。
