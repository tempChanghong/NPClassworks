# UI.5 第一轮：缩小 PWA 首次安装的预缓存清单

日期：2026-10-03。范围：NPClassworks 前端生产构建的 Workbox 预缓存清单。

## 证据与调整

基线构建的 `sw.js` 预缓存清单包含 108 项、102 个不同文件，文件原始大小去重后合计 3,540,720 字节。其中旧 `banner.png` 单独占 665,940 字节。当前应用源码和分享元数据均不引用该文件；[品牌资料说明](../../images/branding/README.md)也明确它只是保留的旧横幅。

在 `vite.config.mjs` 的 Workbox `globIgnores` 中加入 `banner.png`，并在构建校验中阻止它重新进入预缓存。文件本身仍在 `dist/banner.png`，线上如有直接访问链接仍可获取；现有音频、背景图和应用功能分块的缓存规则没有改变。

| 指标 | 调整前 | 调整后 | 差异 |
| --- | ---: | ---: | ---: |
| 预缓存条目 | 108 | 107 | −1 |
| 不同文件 | 102 | 101 | −1 |
| 不同文件的原始大小合计 | 3,540,720 B | 2,874,780 B | −665,940 B（18.81%） |

计算来自同一源码构建前后的 [清单记录](before.json)与[调整后记录](after.json)，可用 [检查脚本](inspect-precache.mjs) 对 `dist/sw.js` 和构建产物重新计算。表中大小是文件字节数，**不是生产网络传输量、首屏下载量或启动耗时**；重复清单 URL 按文件去重，不把同一资源重复计费。

## 验证与边界

- 生产构建、`pnpm run pwa:validate`、全仓库 ESLint 和 `git diff --check` 通过；`dist/banner.png` 仍存在。
- 真实 Service Worker 的 3 项浏览器回归通过：教师未保存草稿下的更新拦截、已安装 PWA 离线重载与恢复上传、升级期间待上传作业保留。
- 本次没有在真实手机或教室一体机上量测冷／热启动、耗电、长时间帧率；缩小预缓存不能直接推断这些指标改善。下一轮应在目标设备上记录网络、缩放、数据量和电源模式后再处理图标字体、持续视觉效果或更新频率。

复现：在仓库根目录运行 `pnpm run build`，再运行 `node docs/ui5-performance-20261003/inspect-precache.mjs dist`。本轮只修改前端缓存清单，没有修改后端、数据库或线上服务。
