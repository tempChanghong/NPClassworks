# UI.5：预缓存与字体加载的有据调整

日期：2026-10-03。范围：NPClassworks 前端生产构建的 Workbox 预缓存清单。

## 证据与调整

基线构建的 `sw.js` 预缓存清单包含 108 项、102 个不同文件，文件原始大小去重后合计 3,540,720 字节。其中旧 `banner.png` 单独占 665,940 字节。当前应用源码和分享元数据均不引用该文件；[品牌资料说明](../../images/branding/README.md)也明确它只是保留的旧横幅。

在 `vite.config.mjs` 的 Workbox `globIgnores` 中加入 `banner.png`，并在构建校验中阻止它重新进入预缓存。文件本身仍在 `dist/banner.png`，线上如有直接访问链接仍可获取；现有音频、背景图和应用功能分块的缓存规则没有改变。

| 指标 | 调整前 | 调整后 | 差异 |
| --- | ---: | ---: | ---: |
| 预缓存条目 | 108 | 107 | −1 |
| 不同文件 | 102 | 101 | −1 |
| 不同文件的原始大小合计 | 3,540,720 B | 2,874,780 B | −665,940 B（18.81%） |

计算来自同一源码构建前后的 [清单记录](before.json)与[调整后记录](after.json)，可用 [检查脚本](inspect-precache.mjs) 对 `dist/sw.js` 和构建产物重新计算。表中大小是文件字节数，**不是生产网络传输量、首屏下载量或启动耗时**；重复清单 URL 按文件去重，不把同一资源重复计费。

## 验证与边界

- 生产构建、`pnpm run pwa:validate`、全仓库 ESLint 和 `git diff --check` 通过；`dist/banner.png` 仍存在。
- 真实 Service Worker 的 3 项浏览器回归通过：教师未保存草稿下的更新拦截、已安装 PWA 离线重载与恢复上传、升级期间待上传作业保留。
- 本次没有在真实手机或教室一体机上量测冷／热启动、耗电、长时间帧率；缩小预缓存不能直接推断这些指标改善。后续应在目标设备上记录网络、缩放、数据量和电源模式，再考虑继续裁剪字体内容、持续视觉效果或更新频率。

复现：在仓库根目录运行 `pnpm run build`，再运行 `node docs/ui5-performance-20261003/inspect-precache.mjs dist`。本轮只修改前端缓存清单，没有修改后端、数据库或线上服务。

## 第二轮：避免重复预加载图标字体

用 [三端加载采样脚本](measure-role-load.mjs)在本机 Chromium 153、4 倍 CPU 限速、回环网络和 12 条合成作业下，各采集 3 次独立冷开与 3 次已安装 PWA 重载。冷开基线发现生成的 HTML 同时预加载 MDI 的 EOT、TTF、WOFF、WOFF2；浏览器实际下载了 TTF、WOFF 和两次 WOFF2，而 CSS 自身已提供按浏览器能力选择格式的 `@font-face`。

把 `unplugin-fonts` 的自定义字体自动 preload 关闭后，CSS 字体声明仍保留，HTML 不再强制下载旧格式；构建校验阻止图标字体 preload 回归。相同采样中，三端冷开都只请求一次 WOFF2，静态资源请求各减少 3 次。

| 冷开场景 | 调整前静态资源 transferSize 合计 | 调整后 | 差异 |
| --- | ---: | ---: | ---: |
| 学生手机 390 × 844 | 4,287,507 B | 1,987,747 B | −2,299,760 B（53.64%） |
| 教师电脑 1440 × 1000 | 4,377,604 B | 2,077,844 B | −2,299,760 B（52.53%） |
| 班级大屏 1920 × 1080 | 4,287,507 B | 1,987,747 B | −2,299,760 B（53.64%） |

原始记录见[调整前](role-load-before.json)与[调整后](role-load-after.json)。这里的 `transferSize` 是本地 Chromium Resource Timing 对**同源静态请求**的记录，包含本地 HTTP 开销；不是线上压缩传输量。已安装 PWA 的资源记录均为 0 B，但这只说明同源静态资源由缓存满足，不代表 API 没有网络请求。

首张内容可见时间的 3 次中位数分别为：学生 994→1173 ms、教师 1331→1470 ms、大屏 1197→1156 ms；变化方向不一致。这个样本只证明无用字体请求被消除，**没有证明启动或交互耗时改善**。真实移动网络、系统字体、不同浏览器、旧教室设备和长期运行还需现场量测。

第二轮的生产构建、PWA 构建校验、全仓库 ESLint 通过；学生、教师、大屏展示与 PWA 离线／升级相关的 10 项浏览器回归通过。

## 第三轮：班级大屏短时重复操作与空闲基线

使用[可复现脚本](measure-screen-session.mjs)连接本地 E2E 服务，给大屏加载 30 条长作业、20 条通知，在 1920 × 1080 的无头 Chromium 153 中施加 4 倍 CPU 限速。分别以“高效”和“标准”显示模式，预热一次放大视图后快速开关 10 次，记录浏览器 CDP 指标；继续前台空闲 30 秒，在末尾触发垃圾回收，再模拟页面冻结 10 秒、恢复并开关一次放大视图。脚本也记录页面异常、长任务和实际使用的底栏模糊效果。原始逐次数据见[采样记录](screen-session-local.json)。测试机器为 Windows 10.0.26300、Core Ultra 9 275HX、31.4 GiB 内存，网络为本机回环。

| 模式与阶段 | 事件监听器 | DOM 节点 | JS 堆使用量 | 长任务累计次数 |
| --- | ---: | ---: | ---: | ---: |
| 高效：预热后 | 1,552 | 6,416 | 19.03 MB | 14 |
| 高效：10 次开关后 | 2,855 | 7,735 | 22.79 MB | 34 |
| 高效：空闲并回收后 | 1,552 | 6,416 | 19.54 MB | 34 |
| 高效：冻结恢复后 | 1,552 | 6,416 | 19.55 MB | 37 |
| 标准：预热后 | 1,552 | 6,416 | 19.01 MB | 13 |
| 标准：10 次开关后 | 2,855 | 7,735 | 22.81 MB | 33 |
| 标准：空闲并回收后 | 1,552 | 6,416 | 19.53 MB | 33 |
| 标准：冻结恢复后 | 1,552 | 6,416 | 19.54 MB | 36 |

两种模式在快速操作时都有短时计数上升；2 秒后仍可观察到，30 秒空闲后已明显回落，垃圾回收后节点和监听器均回到各自起点。通过 CDP 将页面置为 `frozen` 再恢复为 `active` 后，内容卡片仍为 50 张，放大视图仍可开关，节点和监听器保持在起点，页面没有报错。高效模式实际取消了底栏 `backdrop-filter`，标准模式为 `blur(14px)`。这次单轮采样没有显示放大视图在 10 次开关后留下持续增长的节点或监听器，但**不能据此证明整节课或全天运行无泄漏**，也不能用两组近似的主线程时间判定高效模式更快。

本次未接入真实麦克风、外接大屏、旧教室设备或真正的后台标签页。无头 Chromium 切到新标签页时没有把原页面标为 `hidden`，因此使用 CDP 页面生命周期接口模拟冻结与恢复；这只能验证恢复后的功能，不能代替设备上的前后台切换。CDP 的 JS 堆不包含浏览器和 GPU 的全部内存，CPU 限速也不等同于低配设备。现场验收仍需覆盖真实设备上长时间展示、切后台再恢复、持续噪声监测、不同背景与实际网络。复现时先运行 `node scripts/serve-e2e.js`，再运行 `node docs/ui5-performance-20261003/measure-screen-session.mjs`；只使用本地模拟 API，不连接 Docker、生产环境或真实学生数据。
