# UI.4 配套界面：大屏设备管理

日期：2026-10-03。范围：NPClassworks 学校管理中的“大屏设备”、设备账号列表、新建账号，以及同页的全校作业快捷截止时间。延续 [UI 综合评审](../NPCLASSWORKS-UI-DESIGN-REVIEW.md)第 8、13 节的任务顺序：先找到设备和当前状态，再处理新建与全校配置。

## 页面调整

1. 学校／学期仍由左侧管理范围选择器控制。桌面内容区改为只显示一行范围摘要和设备登录提示，移除了重复的两个选择框；手机直接使用顶部可见的范围选择器，避免再显示一张重复摘要卡。
2. “已分配大屏”及搜索、值守状态进入页面前部。保留列表读取时间、刷新失败时的旧快照警告，以及在线、需关注、离线等原状态语义。新建入口放在列表标题旁；账号表单改为对话框，创建失败时保留输入，取消含草稿时先确认，Escape 关闭空表单后焦点返回入口。
3. 手机默认收起搜索与筛选，启用筛选后保留可见；设备行只显示班级、账号、激活状态与值守标签，完整心跳和运行信息仍在桌面列表中。新建弹窗的提示文字与后续字段留出间距。
4. NPEP 设备互联入口仍在设备列表之后；“作业快捷截止时间”移到标明“全校作业设置”的后段。编辑、保存、撤销、权限、全校配置校验及设备指令语义未改变。

## 验证与边界

本地生产构建、受影响文件 ESLint 与学校管理浏览器回归 18 项全部通过。浏览器回归覆盖账号创建／编辑、桌面和手机操作、列表刷新失败后的旧快照、跨学校响应竞争、全校快捷设置的保存和离开保护、权限边界；另有焦点返回及创建失败重试场景。后端授权行为沿用现有独立测试，本轮没有修改服务端或发布到生产。

本次完成的是 UI.4 中最明显的配套管理流程。真实学校管理员仍需验证多学校、多学期和大量设备时的扫描效率；NPEP 实际设备状态与心跳依然要以现场运行记录确认，不能从合成“在线”夹具推断生产设备正常。
