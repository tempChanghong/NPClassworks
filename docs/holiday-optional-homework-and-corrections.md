# 放假汇总、必做/选做与今日更正

## 放假作业汇总

学生页和大屏增加“放假作业汇总”，教师工作台也提供入口，可选择自己负责的教学空间。默认假期从当前作业板日期开始，共七天；可修改清单名称、假期起止日期及向前查找作业的起日。整个查找区间最多93天。

按作业板日期查询向前查找范围，并额外按假期截止日期查询，合并、去重、按科目排列。例如八月布置、十月假期截止的作业，即使八月不在作业板查找区间内，也能被纳入。默认勾选假期内布置或截止的记录；假期前布置且没有假期截止日期的内容可手动选入。没有截止时间且早于查找起日的作业需要向前调整查找日期。

这是一份本次核对和导出的清单，不另行创建发布内容，也不跨设备保存勾选结果。清单沿用现有打印/PDF和分页PNG功能，保留教师确认、选做、需带物品、提交说明和原作业板日期。内容以本次成功加载为准，不包含本机尚未上传的作业。修改日期/班级会取消旧请求、清空旧结果和导出入口；任意一页读取失败时不会用部分结果生成清单。

## 必做与选做

普通教师编辑器保持原有“正文”；点击“添加选做内容”后，正文标为“必做内容”，另行填写最多6000字的选做内容。清空选做内容可恢复普通作业展示。选做数据保存在 `Publication.contentJson.optionalContent`，不需要新增数据库列。

展示覆盖作业卡片、临时放大、抄写模式、周总览、发布前预览、历史、教师待处理、打印和图片。选做变化进入冲突比较、大屏两分钟更正提示、今日更正和教师待处理差异；教师列表也可搜索选做文字。

个人模板保存选做内容，支持同一套填空语法。套用模板会替换或清空选做内容；老客户端编辑模板而不发送新字段时后端保留已有值。切换“今日无作业”时不会提交选做内容。大屏录入器仍只编辑已有的基础字段，展示教师维护的选做内容，保存时不覆盖这些元数据。

## 查看今日更正

学生页和大屏提供“查看今日更正”，主动读取服务器修订，不依赖当前大屏曾经展示过旧版，因此新打开页面也能回看。范围是**当前作业板日期、当前所选班级的可见作业**，更正时间按北京时间的今天计算。显示改前、改后、版本、修改时间和本次更正原因。

新增公开路由 `/api/v2/publications/feed/:id/corrections` 与大屏令牌路由 `/api/v2/classroom-screens/feed/:id/corrections`。前者沿用学生公开作业板的教学空间边界，后者从绑定计算范围，不接受客户端扩大范围。接口每次扫描20条修订，返回向前分页游标；前端完整读取后再展示。

只比较连续且当时已发布的两个版本，并要求两个版本及当前作业均对所选教学空间可见。首次创建、草稿转发布、发布前的定时内容修改、撤回记录及已清理正文不作为可展示的内容更正。输出仅包含标题、正文、截止时间、选做、提交说明、需带物品及更正原因等允许展示的字段，不返回账号、任意元数据或原始快照。仅更正原因变化不算内容变化。

这是按需读取的快照。网络失败明确提示，切换范围或关闭时取消请求并清除结果，不把失败当作暂无更正。快照读取后，若作业列表收到版本、状态变化或读取失败，窗口会清除旧记录、取消未完成请求并提示刷新，避免继续展示撤回或再次修改前的结果。原有两分钟大屏提示保持运行。

## 验证与部署

- 新增日期范围、分页合并、假期前作业、导出转义、选做模板和后端可见性过滤单元测试。
- 新增真实 PostgreSQL + HTTP + 浏览器测试，覆盖教师发布选做、模板旧客户端兼容、打印、删除选做、晚打开的大屏读取更正、草稿隔离、撤回后的访问拒绝、假期勾选及图片导出。
- 前端489项单元测试、后端182项常规测试通过（16项数据库条件测试按默认配置跳过）。隔离 PostgreSQL 的全链路27项全部通过；补充模板套用和历史展示验证后，针对性的6项全链路回归也通过。完整浏览器127项、契约测试3项、Lint、生产构建和PWA校验通过。最后补充的教师选做搜索与待处理展示/差异改动通过相关单元、全链路回归及构建验证。
- 无需数据库迁移，无需修改部署代理。建议前后端配套更新：旧前端不会展示选做内容，新前端使用更正回顾需要新版后端。
- 未提交、推送或部署。

## 本机测试环境恢复

本轮启动隔离数据库测试时，Docker Desktop 再次因 `dockerInference` 运行时套接字无法清理而退出。确认 Docker 进程已退出、相关目录仅含套接字后，将 `%LOCALAPPDATA%/Docker/run` 与 `%LOCALAPPDATA%/docker-secrets-engine` 分别重命名为同级 `run-backup-20260914` 和 `docker-secrets-engine-backup-20260914`，保留原对象，再启动 Docker 生成新的运行时目录。CLI 随后正常连接引擎。没有恢复出厂设置、删除镜像/卷或修改 Docker 数据磁盘；这次恢复不代表已消除故障复发原因。

Docker 官方仓库中有[相同启动报错的报告](https://github.com/docker/desktop-feedback/issues/625)，其中也未确认根因。
