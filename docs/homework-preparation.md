# 需带物品清单

## 使用方式

教师在作业编辑器中选填“需带物品”，并选择独立的“携带日期”。例如：数学作业填写“圆规、直尺”，携带日期选择明天。最多500字，可换行。填了物品后必须指定有效日期，保存失败会保留输入。

事项随作业一起发布、修改、撤回及恢复历史。今日无作业标记也可以附带准备事项；本功能目前作为作业的可选信息，不增加独立的发布类型。

学生页和大屏会集中列出所选班级的需带物品，标明日期、科目、班级及教师确认状态。今天、明天分别标注“今日需带”“明日需带”。来源作业即使布置在更早的日期，仍会显示未到期的事项；草稿、尚未到发布时间的作业、撤回内容及其他班级的事项不进入当前清单。

集中清单以北京时间判断携带日，携带当天结束后自动隐藏。切换到未来作业板日期时，只列该日期起的事项。隐藏不删除记录，原作业详情及版本历史仍保留原物品和日期；恢复旧版本保留其原携带日期，已过期事项不会重新进入当前清单。

打印和图片清单包含需带事项，即使当天没有作业也可导出。作业正文附带的物品日期也保留在单项内容中，查看历史日期时可据此核对。

## 模板与复制

个人作业模板可保存常用物品，也支持“〔工具〕”等填空项。模板不保存携带日期；套用包含物品的模板后需要重新选择日期。模板没有物品时，保留编辑器中原有的物品设置。

复制为新草稿、整日复制作业时，默认清除来源的携带安排，避免沿用旧日期。修改和删除模板使用数据库行锁事务检查版本；旧客户端未发送物品字段时保留已有值，明确发送空字符串时清除。

## 离线与部署

事项和作业一起缓存，断网刷新后可查看已缓存事项并生成清单图片；离线缓存可能不是最新内容。旧格式缓存中的作业如果已经包含物品信息，新前端也能恢复这些已知信息。未曾同步的数据无法凭空恢复。

复用现有发布权限、Socket事件、分页、缓存和历史记录。元数据格式为：

```json
{"preparation":{"text":"圆规、直尺","date":"2026-09-13"}}
```

存储在已有 `Publication.contentJson` 中，无需数据库迁移。新增查询参数 `includePreparations=true` 用于完整分页加载当前作业和跨日期准备事项，再由前端分开展示；未使用该参数的旧客户端保持原有作业板查询范围。

需配套更新前后端，建议先更新后端。无需修改部署代理或服务器配置。

## 验证范围

- 严格日期、500字长度限制、北京时间到期边界、旧格式缓存兼容。
- 教师录入 → 实际 PostgreSQL → Socket更新 → 大屏集中展示。
- 来源作业移到前一天后事项仍可见；离线刷新、打印和PNG生成。
- 102条事项完整分页；草稿、未到发布时间和其他班级隔离。
- 撤回、恢复版本和清除事项；模板套用不继承携带日期。
- 旧客户端编辑模板保留物品；同一版本连续多轮并发修改只有一次成功。

针对性验证命令：`node --test tests/homeworkPreparation.test.js`、`pnpm test:e2e:fullstack tests/fullstack/homework-preparation.spec.js`。
