# 大屏内容状态、周总览保留与导图响应

日期：2026-09-12。

## 行为

- 大屏只有在网络和实时连接正常、上传队列无异常、内容加载成功且未使用缓存时显示“实时同步”。内容请求中显示“正在更新内容”，失败显示“内容更新失败”。离线、队列异常等状态仍有各自的提示。
- 点击同步指示灯可查看连接状态、内容加载结果及当前显示内容的更新时间。时间来自该份内容的 `generatedAt`，读取缓存不会把它改成当前时间。“没有待提交作业”只描述本机上传队列，不再表示内容已经更新。
- 一周总览在同一班级范围、周、查看方式下刷新时保留上次完整结果。失败后显示警告和上次成功加载时间；成功的空结果也属于可保留结果。切换周或查看方式会清空旧结果，切换班级范围或关闭对话框会取消请求并清空。401/403 权限拒绝会清空旧内容。
- 导出图片沿用原来的分页算法，通过同一生成器提供同步和分段执行方式。浏览器排版每处理约 256 个字符检查一次时间预算，累计约 8 毫秒后让出主线程，允许关闭预览取消任务。页数上限与完整保留正文的要求不变。
- 字体最多等待 3 秒，单张图片编码最多等待 10 秒；超时会提示重试。关闭时立即结束等待并释放画布和已生成的图片 URL；迟到的编码结果不会重新出现在预览中。

## 排版测量

运行 `node tests/benchmarks/homework-images.mjs`。脚本只启动本机 Chromium，使用 Canvas 实际测量文字；不需要 API、数据库或生产数据。测试 1 万字和 10 万字单段正文，分别在正常 CPU 和 6 倍 CPU 降速下记录排版总时间、零延时定时器等待时间及取消结果。

本次在其他测试结束后单独测量，10 万字、95 页、6 倍 CPU 降速的结果：

| 测量 | 同步排版 | 分段排版 |
| --- | ---: | ---: |
| 定时事件等待 | 163.1 ms | 8.4 ms |
| 完整排版耗时 | 162.3 ms | 720.8 ms |
| 单独触发取消的完成时间 | 同步阶段无法响应 | 26.0 ms |

分段执行以额外调度开销换取响应能力，不能把它描述为导出速度提升。以上仅为一次本机合成负载结果，不包含 PNG 编码，不代表课堂硬件耗时；短文本可能在下一次事件执行前就已经完成。保留脚本用于后续实机复测，没有把机器相关的耗时阈值写入 CI。
