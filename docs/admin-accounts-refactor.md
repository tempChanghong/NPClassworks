# 账号与管理员逻辑拆分

本轮将学校管理页中的账号列表、筛选、管理员创建、PIN 重置、启停、注销、账号摘要及角色选项迁入 `src/composables/admin/useAdminAccounts.js`。

管理页在 setup 中创建一次该模块，继续向现有 `AdminAccountPanel.vue` 传递同样的 refs、选项和事件。管理页模板、账号面板及本人账号按钮限制未修改。

## 保留在父页面的职责

- 管理员身份、学校上下文、登录与学校权限刷新。
- 全局成功/错误消息、初始凭据及下载、账号名册下载。
- 跨模块共享撤销提示、教师名册刷新和导航离开确认。
- 原有学校变化及标签页切换时的加载触发。

模块接收这些共享 refs 和刷新回调，不创建第二份凭据或撤销状态。创建和注销成功后的 Promise.all 刷新组合保持原样；失败处理、PIN 提示与校验、危险操作确认、撤销时固定学校 ID 均按原函数迁移。OWNER 可选 OWNER/ADMIN、ADMIN 仅可选 ADMIN 的原有选项逻辑及角色变化 watcher 保持不变。

## 验证方式

先在未拆分的实际管理页上运行新增的 `tests/adminAccountFlows.test.js`，5 项通过；迁移后使用相同测试再次通过。测试通过真实 Vue setup、路由和 API 客户端连接本机 HTTP fixture，覆盖失败保留输入和凭据、取消操作不写入、PIN 重置、启停撤销、注销后的刷新、角色变化及实例隔离。没有用源码匹配代替这些交互断言。

浏览器用例沿用 `tests/e2e/admin-screens.spec.js`，增加桌面 OWNER、窄屏 ADMIN 和非管理员场景，验证角色选项、本人操作限制、创建与未保存提示、实际 CSV 下载、取消 PIN 重置、启停撤销和筛选。API 使用测试夹具，不替代后端权限验证。

本轮不修改后端、数据库、部署流程或部署代理。未推送或部署。
